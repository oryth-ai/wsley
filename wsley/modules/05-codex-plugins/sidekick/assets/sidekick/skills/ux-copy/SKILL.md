# UX Copy

用清楚、准确的界面文字帮助使用者识别对象、判断状态并完成操作。沿用产品语言、品牌语气和已有术语，使同一事实在按钮、页面、通知与错误反馈中表达一致。

## 情境与依据

读取相关界面、用户任务、实际状态和项目文案规范。确定动作的对象、结果、等待时间、成本、可撤销性和失败后的下一步；文字不能替产品决定尚未明确的行为。

从现有资料确认目标语言、语气、长度和平台限制。普通局部改写直接执行，只有会改变业务含义或核心风格的缺口才需要澄清。只要求文案时按对应范围交付，不自动重做整个页面。

## 按状态表达

| 界面内容 | 应表达的事实 | 核对重点 |
| --- | --- | --- |
| 主操作 | 动作与结果，例如“保存更改” | 文案对应实际提交范围，不用含糊的“确认”掩盖影响 |
| 错误 | 已知问题、可说明的原因与可执行下一步 | 结果未知与业务拒绝分开，不暴露内部异常或归咎用户 |
| 空状态 | 当前对象、为空的原因和适用起点 | 首次使用、筛选无结果、无权限和读取失败分别处理 |
| 确认对话框 | 对象、数量、影响和可撤销性 | 按真实后果措辞，不能把可恢复操作写成永久销毁 |
| 等待与完成 | 正在发生什么、是否已受理或真正完成 | 不伪造进度、剩余时间和后台成功 |
| 引导与帮助 | 眼下需要理解的概念或下一步 | 说明出现在困难附近，不复述显而易见的控件 |

优先使用具体名词和动作，保留判断所需的单位、范围、日期与成本。精简删除重复和装饰性解释，不能删除业务事实、状态差异或恢复入口。语气随情境调整，失败与风险反馈保持冷静、可操作。

## 术语与本地化

同一概念使用同一名称，避免把数据库、模块或接口字段直接暴露为产品术语。术语存在业务歧义时交给 [domain-modeling](../domain-modeling/SKILL.md)，语言资源、占位符、复数和地区格式使用 [i18n-expert](../i18n-expert/SKILL.md)。

可访问名称应包含可见标签的关键文字；图标、状态和错误不只靠颜色传达。为翻译保留上下文，避免拆句拼接、隐含性别、双关和无法本地化的图中文字。

## 验证与交付

对照真实状态和布局核对最终措辞，覆盖受影响的成功、拒绝、未知结果与恢复路径。实际修改遵循 [disciplined-dev](../disciplined-dev/SKILL.md)，同步共享文案、语言资源及相关调用方。

交付推荐文案和必要理由；只有确实存在不同取舍时才给备选，不强制固定数量。缺少业务事实或未查看实际布局时说明具体限制，不把文字改写宣称为已证明转化率改善。
