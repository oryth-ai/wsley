# 精修与强化

## 基线与范围

读取真实页面、共享规则、代表内容及相邻流程，确认要保留的品牌、行为与用户指定风格。能运行时先看实际画面，已有发现与有效证据直接承接。只有链接或截图时，区分分析、独立重建与修改源码，不默认复制整站或另做平行 HTML。

精修在既有视觉身份内提高完成度，明确要求重设计时采用 [方向与构思](art-direction.md)。用户只要求指出问题时由 [frontend-audit](../../frontend-audit/SKILL.md) 负责；已经授权改善时继续实施，不再要求批准同一范围。

## 选择改进方式

将“高级感不足”“模板感”或“AI 味”转成具体位置、表现与影响，再选择处理深度：

| 观察到的差距 | 合适的改进 |
| --- | --- |
| 主体弱、区域等权、视线没有落点 | 强化构图、主次比例、字体对比或真实素材，让重点获得足够面积 |
| 各处同时强调、边框与特效争夺注意 | 降低次要区域的强度，保留有价值的重点和产品语气 |
| 内容重复、路径绕、用户难以决定 | 按任务重组表达与层次，保留判断和恢复所需信息 |
| 方向已经成立，但对齐、换行、层次与状态粗糙 | 校准共享规则及局部光学细节，补齐完整路径的完成度 |
| 页面与内容可以直接换成任何产品 | 引入真实产品机制、画面、领域材料和措辞，形成有依据的辨识度 |
| 视觉方案无法承载目标，用户明确要求换方向 | 进入重设计，保留产品事实与行为，重新组织视觉系统 |

强化不是让所有东西更大、更亮或更动。优先放大当前方向中最有效的手法，建立有力度的主位和安静的支撑；降低噪声也不是将界面清空为灰底文字。色彩、渐变、卡片、emoji 或某种字体本身不能证明缺陷，不能用禁止名单替代设计判断。

## 找到共同原因

区分缺少可复用规则、未采用已有组件、结构或流程不匹配，以及局部实现粗糙。多处间距、字体、图标和反馈无故不同时，从负责它们的 token、组件和组合规则统一处理；单个特例不自动升级为全局设计系统。

先解决阻断任务、错误结果和访问障碍，再按依赖改善结构与层级，最后校准材料、细节和代码。改进方向已经明确时一起实施相关层次，不按固定遍历次数反复改写同一文件，也不为了先做细节而放任主体与流程未完成。

## 让产品性格更清楚

让最重要的内容成为可见主体：产品画面、领域图形、作品、排版或清晰的关键状态，按 [图像与材料](imagery.md) 选择。重点通过 [布局与空间](layout.md)、[排版](typography.md) 和 [色彩与主题](color-and-theme.md) 形成，周边控件保持同一语言。

在有意义的完成、首次使用、等待或恢复时加入具体而适度的反馈。文案先说明对象、结果和下一步，情绪表达与后果相称，不用玩笑淡化损失，也不为普通操作制造庆祝。运动与触感按 [表面与动效](motion-and-surfaces.md) 实现，真实进度与频繁使用优先。

精简内容仍保留单位、范围、必要精度、依据、错误和恢复。重写措辞采用 [ux-copy](../../ux-copy/SKILL.md)，组件与实际接入采用 [组件与实现依据](components.md)。未授权的业务变更、功能增删和品牌替换不隐藏在精修中。

## 同条件复核

按 [验证与交付](verification.md) 比较同一内容、视口、主题和状态，核对原问题、共享调用方及新影响。缩小画面看结构，真实尺寸读内容，实际操作检查路径和反馈；确认整体比原先更有方向，同时保持可用。

交付主要改进、设计取舍、实际验证和剩余限制。已有问题解决且目标成立时完成，不以任意评分、固定截图次数或持续更换风格延长工作。截图与对比材料仅在后续消费或交付确需时保存，不自动新增宣传视频、演示页面或过程报告。
