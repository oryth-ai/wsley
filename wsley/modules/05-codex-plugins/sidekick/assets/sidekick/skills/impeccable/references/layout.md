# 布局与空间

## 构图与阅读顺序

先确定页面的主任务、最重要的信息及下一步，再分配空间。缩小画面或暂时忽略文字细节，仍应看得出视觉中心、主要分组和阅读路径。主体可以是作品、标题、产品画面、关键状态或工作区，不能让所有内容获得相同面积和强调。

用比例和位置建立层级：主次区域、宽窄关系、对齐轴、留白和必要的不对称。变化应由内容优先级驱动；同一类反复出现的内容保持规律，不同职责的区域允许不同构图。整页连续排列等大的卡片、表格或文字块时，先判断这些区域是否真的具有相同职责。

首屏需要建立方向并让主要路径可发现，后续区域展开依据和操作。不同区域可以有疏密、背景、图文比例和节奏的变化，变化仍须属于同一套视觉语言。营销页的展开顺序、工作界面的稳定分区和长文的阅读节奏分别设计。

## 载体与分组

| 信息关系 | 合适的起点 |
| --- | --- |
| 同构记录比较、排序与批量操作 | 表格或结构化列表，保留列对齐、选择范围与操作语义 |
| 单个对象及其属性 | 有层级的语义字段与详情分组 |
| 多步输入或复杂编辑 | 按决策和依赖组织的表单、工作区与步骤 |
| 时间、趋势或数量关系 | 相应的时间线、图表或可视化，保留单位、范围与精确值入口 |
| 作品、商品或差异明显的内容对象 | 内容驱动的图文组合、列表或卡片 |

选择载体后继续设计空间和层级。表格可以精确而优美，卡片也可以杂乱；不能按减少某类控件的数量衡量提升。数据面板需要说明重要变化、当前范围与下一步，不能仅把接口字段变成一屏等权指标。

组内紧凑、组间充分分离，让距离本身表达关系。检查标题与所属内容、标签与字段、说明与操作的亲近程度，结合文本行高调整光学间距。使用项目间距体系，必要例外由实际构图承担，不将所有值机械吸附到同一刻度，也不靠到处加分隔线代替分组。

## 密度与持续操作

密度来自信息重要性、使用频率、设备与内容，不由“高级”二字决定。高频工作区可以紧凑，关键判断和危险操作需要充分辨认；低密度页面也需要有价值的主体，留白不能替代缺失内容。

核对导航、标题、工具栏、筛选、结果和详情的范围。筛选靠近其作用区域，局部操作不伪装成全局动作，选中与展开保持不同语义。弹窗用于需要隔离焦点或确认的任务，长流程和持续比较按实际需要安排页面或工作区。

## 响应式与内容压力

根据内容和容器失效的位置设置断点，设计重新分配与折叠后的阅读顺序；移动端需要可用的构图，不能只是把桌面等比缩小。保留主次任务、上下文、适用的固定操作与安全区域，避免固定导航遮挡内容和焦点。

检查 flex 子项、网格轨道、最小尺寸与收缩边界。确需收缩的子项可用 `min-width: 0`，轨道可按需要使用 `minmax(0, 1fr)`；从实际约束定位原因，不全局覆盖。宽表可以合理滚动，文本溢出按内容处理，不能一律截断或隐藏。

用长短标题、空内容、大量记录、缩放和实际支持语言验证布局，复用 [组件状态与压力验证](component-states.md)。在目标视口及中间宽度查看整体与局部，确认改动同时改善阅读路径、空间关系和操作；单张首屏截图不能证明所有状态成立。
