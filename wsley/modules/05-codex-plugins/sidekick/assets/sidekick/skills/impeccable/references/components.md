# 组件与实现依据

## 项目上下文

读取所属应用的依赖、锁文件、包管理器、框架与路由、路径别名、组件目录、主题及样式入口。monorepo 中确认消费应用和共享 UI 包各自的职责，不在仓库根目录推测实际输出位置。

先查看代表页面、共用组件和真实调用方，明确已有组件的 API、变体、状态、可访问性与本地定制。配置和官方文档用于解释来源，当前项目源码决定实际可调用的接口；发现冲突时查明版本或定制原因，不用更新依赖掩盖差异。

## 复用与查找

| 当前情况 | 处理方式 |
| --- | --- |
| 本地组件及其变体已经满足需求 | 直接组合，沿用项目别名、状态语义和样式规则 |
| 本地缺少必要能力，所用组件体系有官方实现 | 查阅匹配版本的文档、示例及源码，核对引入成本后按需集成 |
| 项目采用或任务选择了 shadcn/ui | 使用 [shadcn](../../shadcn/SKILL.md) 衔接官网预览、registry 源码和项目适配 |
| 其他组件体系或非 React 项目 | 使用对应体系的官方资料，保留框架和现有组件，不将 shadcn 示例直接移植为新依赖 |
| 任务需要项目特有表达，已有组件无法合理承载 | 在负责该行为的位置实现必要扩展或新组件，保留状态、语义和验证边界 |

参考用于解决具体缺口。局部修改和已有明确方案不要求重新搜索整套模板；缺少具体依据时再查找，不把官网样例、热门组件或社区 registry 当作必选清单。

## 示例与代码

按实际任务寻找组件、组合区块、图表或页面示例。视觉判断查看真实渲染和必要交互，接口判断读取文档与源码；两种证据分别取得，不能以安装完成代替看过效果，也不能根据画面推断 API。

核对示例的组件库、版本、主题、响应式结构、图标和依赖，明确借鉴的布局机制与需要保留的项目行为。上游默认字体、配色与演示内容不自动替代已确认方向；宣传主张、客户名称和统计数据不得冒充产品事实。

取得完整区块时，沿文件清单追踪导入的子组件、hooks、工具、样式、数据和资源。选择与当前目标有关的部分集成，同步必要调用方，不只复制入口 JSX 后留下缺失的实现，也不因示例包含某个功能而扩大产品范围。

## 适配与所有权

跨页面出现宽度、对齐、操作分组或步骤连续性问题时，区分规则、实现和产品状态的归属：项目规范定义选择依据，共享设计系统承载有真实消费者的组合模式，应用持有路由、权限与业务流程。先核对这些边界，再决定调整共用接口或页面组合，不把一组孤立控件当作完整设计系统，也不为单个页面虚构通用模式。

将外部实现归入项目负责该行为的位置，统一路径别名、路由、数据契约、图标、语言资源和设计变量。保留本地组件已经提供的权限、加载、失败及恢复语义；演示中的模拟数据和行为按交付范围接入或明确标识。

优先使用组件已有的语义、变体与组合接口。需要改变共用组件时同步其受影响调用方；避免新建同名平行组件、在页面反复覆盖内部选择器或用包装层隐藏接口冲突。

对原始库、已复制到项目的组件源码、业务组合组件分别维护其真实依赖关系。是否更新库或合并上游源码由任务范围决定，下载示例不构成批量替换本地组件的依据。许可、来源与必要声明随实际采用的内容保留。
