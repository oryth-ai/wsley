# 色彩与主题

## 色彩构图

从产品、品牌、素材和使用环境决定色彩关系。明确主要背景、色彩区域、文字层级、行动和状态各自的角色，再确定颜色在画面中的面积与强度。色彩可以建立气氛、分区与记忆点，也可以支持安静而精确的工作；灰色背景配一个强调色并非所有产品的默认答案。

让最有表现力的颜色落在值得强调的位置。大面积的品牌区域、产品图像或清楚的选中关系可以比到处散布强调色更有力度，周围内容提供支撑与对比。已有方向中的强化首先调整分配、层次和关系，不自动更换整个色板。

品牌原色、装饰色和承载阅读的功能色分别处理。品牌色不适合某个文字组合时，调整背景、位置或必要的功能变体；品牌事实由任务决定。错误、选中和成功同时通过文字、形状或状态表达，不能只依赖颜色。

## 变量与主题

读取主题入口、变量、组件消费者和切换逻辑，沿用实际语义契约。背景、表面、文字、边界、操作与业务状态由负责它们的位置维护，不因采用本资料就将已有名称批量重命名或建立无人使用的色阶。

调整 token 时追踪真实消费者。同一个值可能同时用于文本、图标和底色，一处对比改善可能破坏另一处；需要拆分角色时完整迁移调用方。shadcn 项目按其主题契约扩展，不建立平行变量体系。

明暗主题分别建立表面、文字与状态关系，不机械反相。核对悬浮、按下、选中、焦点、禁用、输入、浮层和遮罩，在系统高对比度下保留必要信息与操作边界。主题选择来自实际使用与产品要求，不按行业标签直接指定。

## 色域与对比

颜色格式采用项目支持范围。OKLCH 等空间可辅助调节感知明度和色度，不要求迁移现有颜色；固定明度或色度不保证不同色相的对比相同。超出目标色域的值检查实际显示与回退。

对具体元素、状态和主题取得实际前景及其绘制背景，再测量适用对比。透明度、父级叠加、渐变、图像、遮罩和混合模式会改变结果，只比较变量声明可能选错配对。图片上的文字检查可能出现的最不利区域，动态内容还需考虑变化范围。

优先使用现有检查器或浏览器工具，明确元素、状态、颜色来源、方法与结果。截图采样受缩放、色彩处理和抗锯齿影响，字缘像素不是 CSS 原始文字色；无法可靠取得背景时说明限制，不编造比值。

适用阈值与例外按 [访问与交互模式](../../accessibility/references/interaction.md) 和项目目标核对。WCAG 与 APCA 是不同计算和判断体系，不能互换结果；占位文字不因 `placeholder` 身份自动豁免。[WCAG 对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 验证

同时检查整体色彩构图和真实配对。修正错误角色、继承与叠加后，核对相关消费者和主题，确认辨识度、阅读、操作与状态同时成立。区分已测量配对、视觉建议和未覆盖部分，一张截图不能证明全站对比合格，颜色减少也不能自动证明设计改善。
