# 方向与构思

## 产品与页面目的

从使用者的场景、真实内容、主要行动和成功条件出发，确定本次设计需要让人理解、相信、完成或感受到什么。提取产品特有的机制、材料和证据；产品名称或行业标签不足以决定全部视觉。

按具体页面选择表达方式，同一产品可以同时包含下列目的：

| 页面目的 | 设计重心 | 可以承担辨识度的材料 |
| --- | --- | --- |
| 说服与转化 | 价值、可信证据、阅读顺序与明确行动 | 主视觉、产品实景、鲜明排版、内容节奏、演示与叙事 |
| 工作与操作 | 工作区、任务状态、信息比较、频繁使用与恢复 | 清楚的界面结构、色彩区域、精确密度、数据表达和有意义的交互细节 |
| 阅读与理解 | 连续阅读、内容层次、定位与引用 | 字体、行宽、段落节奏、图文关系、索引与注解 |
| 展示与体验 | 作品、发现路径、沉浸和记忆 | 摄影、图形、声音或运动、特殊构图和交互；按任务与环境取舍 |

工作界面先成为好用的产品。品牌可以通过排版、色彩、空间、数据和关键细节进入界面，布局与控件仍然支持熟悉的操作。展示页面可以更大胆地改变结构，必要操作仍然可识别、可到达。

## 视觉依据与设计空间

区分已经成立的约束和真正开放的选择。局部组件与新增状态继承所属页面；已有视觉系统中的新页面沿用其语言，开放的空间主要是构图与交互。用户明确要求重设计时，可以重新定义视觉身份，不能因为旧实现存在就将目标缩减为细节修补。

方向来自可描述的视觉系统：领域里的出版物、材料、场所、数据图形、文化和品牌语言，以及与需求相关的优秀产品。参考用于提取比例、节奏、材质或交互原则，不能只给风格起名字，或把互不相关的字体、玻璃、网格和渐变拼在一起。常规而出色的方向同样有效，用户明确选择的风格优先。

需要建立方向时，简要说明：

- 内容与路径：用户先看什么、接着理解什么、主要行动在哪里
- 构图与重点：主体、比例、空间分配、首屏与后续区域的关系
- 视觉语言：字体角色、主色区域、素材、表面及少量有识别度的手法
- 交互与延展：关键状态或运动如何支持方向，窄屏和相邻页面如何延续
- 实现与取舍：可用组件、素材取得方式、性能成本及必须保护的行为

这些决定优先在对话中承接，已经明确的内容直接采用。需要转入长期设计资料时，遵循项目文档归属与授权，不默认新增设计契约、评选页面或状态记录。

## 设计参考来源

需要补足视觉语言、页面结构或区块表达时，按具体缺口查阅参考。用户指定的参考和已有品牌约束优先，明确的局部修改不要求重新浏览素材库。

| 来源 | 适用内容 | 采用方式 |
| --- | --- | --- |
| [VibePrompts](https://vibeprompts.dev/) | UI 区块与页面布局的提示词、实时预览和 Tailwind 示例 | 按当前任务查找相关条目，对照预览、提示词与示例，提取构图、层级和响应式处理 |
| [VibeUI](https://vibeui.top/) | 设计风格条目、预览页面与设计文档 | 对照同一风格的预览与说明，理解字体、色彩、空间、表面和组件语言如何共同成立 |

从选中的具体条目提取适合当前产品的设计决定，保留来源以便比较与核对；风格名称、提示词和设计说明不能代替对实际效果的观察。参考中的框架、配色、内容和交互按项目要求适配，引用 `DESIGN.md` 不要求在项目创建同名文件或替换已有设计规范。

选定参考后，按 [组件与实现依据](components.md) 选择项目组件来源并接续集成。

## 形成有意义的选择

方向未定且不同方案确有取舍时，围绕真实内容比较结构、字体、素材或运动等关键维度。局部比较尽量固定其他条件，完整方向可以组合多个维度，说明为什么这些选择共同成立。方案数量随实际决策需要确定，不强制竞赛、随机抽取或逐轮批准。

让备选在代表页面、真实内容和相同视口中呈现。结构差异应能从缩略图识别，字体与交互差异需要在实际尺寸和速度下观察；换个颜色或修改描述不算新的方向。复用现有预览，不为比较默认增加生产路由或独立应用。

用户委托 agent 决定时，作出有依据的选择并继续；用户要求选择时，呈现差异与代价后等待相应决定。确认方向后在整个负责范围贯彻，不在实现阶段悄悄改回熟悉模板。

## 从方向进入实现

先完成能体现方向的代表页面或关键流程，再将成立的组合规则推广到相关界面。主体、真实内容、操作和适用状态同时进入实现，避免只做一张脱离业务的视觉卡片。大画面、精致控件和次要状态共同组成质量，不能只精修一个角落。

需要素材时采用 [图像与材料](imagery.md)，需要构图时采用 [布局与空间](layout.md)。参考机制不清时使用 [interface-analysis](../../interface-analysis/SKILL.md)，已有充分设计依据时直接沿 [参考与设计还原](design-reproduction.md) 工作。探索结果交付到用户要求的深度，实现任务继续进入真实项目与验证。

方向确定后将实现收敛到正式负责位置，移除本任务无继续用途的候选、临时选择器和预览，保留用户要求的比较产物。原型制作说明在交付中表达，产品本来需要告知的隐私、存储和能力限制仍在实际界面中可见。
