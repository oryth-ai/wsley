# 表面与动效

## 材料与层次

让背景、容器、边框、阴影和圆角组成一致的空间语言。平面、纸张、透明、光泽或其他材料只有在方向和内容中成立时采用，重点是层次、触感与整体关系。浅色图片是否需要边界取决于背景、裁切与信息关系，不按统一透明度为所有对象描边。

嵌套圆角按真实轮廓、间距与裁切检查。外半径减间距可作为等距轮廓的起点，边框和非均匀间距仍需实际调整。层次可以由底色、边框或阴影表达，不要求每个容器同时叠加所有手法，也不把某个圆角或阴影值设为通用风格。

图标采用一致的字形和视觉重量，在实际尺寸下核对文本基线与可点击区域。字体字重和图标描边没有通用的一一映射，不为统一数值重画图标集。焦点、选择、光标和链接等浏览器表面也应与设计协调，保留其原生能力与可见性。

## 动效的职责

按页面目的决定运动承担多少表达。展示和叙事页面可以围绕主体组织鲜明的动态时刻；工作和阅读界面用运动确认动作、解释变化与维持连续性。完成、首次使用、等待和恢复可以具有产品性格，频繁保存和普通点击仍需及时确定。

明确关键动态、状态连续性和控件反馈之间的关系。通过裁切、遮罩、模糊、光影、颜色、位移或共享元素表达所选方向，选择真正需要的材料；`transform` 与 `opacity` 是可靠基础，但不是全部调色板。反复给每个区块套同一入场动画不能替代动态设计。

运动的距离、时长和曲线服务于变化的意义、频率与设备。短反馈及时，较长序列需要叙事理由；列表可有适当错峰，仍要控制整体等待。等待动画不伪造进度，不为了展示效果延迟真实完成，重要操作不依赖观看整段动画。

## 实现与中断

| 场景 | 实现判断 |
| --- | --- |
| 简单状态切换 | CSS transition 跟随状态，验证快速反向与中断 |
| 多阶段进入、退出或序列 | 使用现有 keyframes、Web Animations API 或项目动效库，明确收尾责任 |
| 滚动或手势驱动 | 保持输入与反馈对应，核对边界、取消、焦点与触摸 |
| 对象连续移动或视图切换 | 按支持范围采用共享元素、FLIP 或 View Transitions，保留可用回退 |
| 复杂路径、弹簧、材质或跨组件协调 | 先核对已有能力，确需时引入与目标相称的依赖 |

keyframes 不等于无法反向，重定向能力由状态模型和 API 决定。Web Animations API 的 `reverse()` 可以反向播放，中断位置、速率和收尾仍须核对。[反向播放说明](https://developer.mozilla.org/en-US/docs/Web/API/Animation/reverse)

进入与状态动画分别建模，数据刷新不重新播放整页入场。入场采用默认可见或可靠回退，避免动效初始化失败就永久隐藏已渲染内容；滚动叙事按支持环境保留连续阅读路径。保留操作名称、焦点和区域；离开、卸载和取消时释放任务拥有的监听、计时器与动画，退出不能永久扣住节点、焦点或滚动。业务成功由业务结果确定。

游戏、计时或强反馈控件还需核对动作节奏、结果可读性与实际状态。随机、资源、次数和存档遵循产品契约，奖励或持久化结果不能只由视觉反馈伪装。

## 性能与偏好

避免每帧交错读取布局和写入样式。合成属性不保证无成本，滤镜、阴影、混合、大面积模糊、canvas 和着色器都需限制作用区域并核对目标设备。`will-change` 只在具体需要的生命周期使用，不能以技巧名称代替测量。

尊重 `prefers-reduced-motion`，减少非必要空间移动并保留可理解的状态反馈。非必要循环在离屏或隐藏时停止，声音和自动播放遵循用户选择。不能为主题切换暂时有杂乱过渡就永久禁用全部 transition。

## 验证

以正常速度实际观看开始、结束、快速重复、中断和反向，检查目标设备、键盘、触摸及减少动态效果。静态截图只证明某一画面；节奏、连续性和性能依赖真实过程。确认关键动态具有产品意义，重复使用仍然自然，移除装饰后功能也完整可用。
