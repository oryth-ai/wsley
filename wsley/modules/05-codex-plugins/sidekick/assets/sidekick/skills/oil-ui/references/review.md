# 运行与评审

## 实际证据

先完成代表页面或关键流程，再推广到相邻页面。普通调整查看目标区域及相邻影响，整页改版检查整体阅读节奏、关键视口和状态，不只看首屏截图。

一批关联修改稳定后集中取证，查看截图中的层级、可读性、裁切、素材质量与布局。动效在正常速度下实际观看，不能用静态图证明节奏或过渡正确。

交互从真实入口到可观察结果，核对刷新后读取、提交失败、重复操作、权限与范围变化。动画和异步任务等待真实状态，不靠任意延时得出成功结论。

## 评审与修正

以前后证据和明确目标判断问题，区分可复现故障、项目规范偏差与审美建议。没有真实图像时不评价已实现视觉质量；没有可靠评分方法时不制造总体分数。

先修复影响多处的共用原因，再处理局部差异。反馈中的建议核对业务事实和已确认方向，不能为了追求评分改写用户目标或反复加入新风格。

复审针对原发现、修正和引入的影响，复用仍有效的证据。独立评审依赖授权与可用环境，不预设固定的执行者、评审次数或通过阈值。

## 完成核验

按实际差异运行项目要求的类型、格式、测试与构建检查，不由设计技能一概禁止必要检查。工具失败、接口错误和依赖问题分别诊断，不能把影响交付的故障当作与界面无关而直接绕过。

交付说明区分实际功能、原型、模拟数据和未验证部分。材料只保存任务需要的内容，位置与清理遵循项目规范；截图、研究与外部资源均不扩大操作授权。
