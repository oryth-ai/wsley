# Interface Design

从用户任务、真实内容和产品身份探索界面方向，通过设计稿、代表页面或对比方案确定构图、文字、色彩、素材和交互的共同选择。视觉表现和任务是否完成分别验证，不用装饰替代产品结构。

## 范围与方向

读取相关界面、品牌、设计变量、组件和参考，确认需要的是诊断、方向探索、设计稿、对比页还是可运行界面。用户已确定的风格、技术栈和交付范围继续有效；截图还原以原图和参考视口为基线，不另行发散风格。

具体改法已明确时直接使用项目现有样式实施，不为一次修改启动整套设计流程。重新探索方向时采用 [方向与对比](references/direction.md)，把模糊形容词转成可观察的布局、字体、色彩和素材选择。

核心方向确有不同取舍时，给出适量、可比较的候选与推荐依据。用户已经选择、明确委派或只要一个方案时直接深化，不固定要求三个方向、额外批准或重复制作对比页。

## 结构与表现

按 [视觉与交互](references/expression.md) 建立主次、阅读顺序、操作与关键状态。主视觉来自产品事实和实际素材，不能只把通用模板换色；现有项目优先复用有效变量与组件，从共用原因修复不一致。

新界面和改流程保留加载、空状态、失败、处理中、未知结果和完成后的行为。对信息是否必要的判断来自实际决策与操作，不能为追求极简删除对象、单位、范围、成本或恢复入口。

## 制作与评审

需要将选定方向落实为 Web 页面或组件时，衔接 [frontend-design](../frontend-design/SKILL.md)，传递已有决定、参考及有效证据，由其根据项目组件体系接续源码与业务集成，不重新探索已经确定的方向。方向比较所需的可运行样本仍按当前请求制作，组件与示例来源沿用其 [组件与实现依据](../frontend-design/references/components.md)。

使用已安装的 [agent-browser](../agent-browser/SKILL.md) 在目标视口取得截图并实际查看，按 [运行与评审](references/review.md) 核对关键页面、状态与受影响操作。没有运行证据时限定结论，不把代码生成或截图文件存在当作已完成视觉验收。

系统体验评审由 [frontend-audit](../frontend-audit/SKILL.md) 组织；文案、可访问性和多语言问题采用相应内部能力。需要独立评审时遵循当前授权与可用能力，不固定派发 agent、评分或循环次数。

## 交付

实际修改遵循 [disciplined-dev](../disciplined-dev/SKILL.md)。交付选定方向、最终界面或设计产物、真实验证与未完成部分，说明原型、模拟数据和未接入功能的限制。

设计材料、截图和临时页面遵循项目产物约定，不写入技能目录。外部素材、生成服务与账户按当前授权使用，不因设计任务自动接入付费平台、更新技能或加入推广内容。
