# 方向与对比

## 产品依据

先确定品类、目标人群、主任务、首屏需要传达的事实和期望动作。参考同类优秀产品时拆解信息顺序、构图和控件语法，说明可借鉴的机制，不复制其业务主张、品牌或资产。

把“高级”“轻盈”“科技”等词转为具体决定，例如文字密度、对比、色彩范围、图片角色、空间节奏和操作反馈。方向的辨识度来自产品，不从固定字体、渐变、网格或卡片模板推导。

## 对比问题

先说明比较要解决的决定，例如内容密度、导航结构、编辑方式或视觉语气。优先围绕一个主要维度选择有实质差异的位置；其他条件尽量固定，让差异能归因于该决定。整体风格探索确需同时改变字体、材质与构图时，将其作为成套方向说明，不声称已经单独验证某个变量。

每个候选说明适用任务、具体选择、预期收益与代价。比较配色时换色本身可以是有效差异，但不能把它包装成不同信息架构。避免一个候选只换装饰、另一个却增加功能，或使用明显不成熟的候选衬托预选答案。

保留已确认的品牌、参考、结构和业务语义，只改变尚未确定的部分。候选数量由真实取舍和任务范围决定，用户委派判断时给出推荐；设计假设不能冒充用户研究或偏好证据。

## 可运行对比

用户需要看实际画面时，复用真实组件、内容、数据、主题与相邻上下文，制作足以辨别方向的代表页面或区域。布局选择应在实际容器中比较，不能只展示孤立卡片；内容、空状态与失败状态的契约在各候选中保持一致。

优先使用已有预览承载；确需临时比较入口时，按 [组件状态与压力验证](../../frontend-design/references/component-states.md) 保留项目环境和组件边界，不默认添加生产路由或重复实现。交付 HTML、截图或文字根据请求确定，只要建议时不额外制作页面。

并排或缩略图用于快速比较构图，最终仍以目标尺寸查看文字、操作与细节，不能将多个页面压缩到一屏当作可读性证据。必要时在同条件下切换候选，保留浏览位置与相关状态；不强制采用固定 URL、选择器布局或键盘快捷键。

## 选择与收敛

按原比较问题解释各候选的取舍和适用条件，不用总体分数替代决定。用户已委派或提出明确偏好时据此选择，仍需用户决定的实质问题才保留候选，不为每一步额外索要批准。

将选定方案带入真实组件与页面，核对共享调用方及原有状态。临时复制、选择器和失效候选按归属与继续用途清理；需要保留的设计比较按项目产物规则管理，不能让未选分支长期成为运行时的隐藏风格开关。

## 参考还原与组件

参考截图采用 [参考与设计还原](../../frontend-design/references/design-reproduction.md) 的视口、来源与差异判断，区分精确还原和允许调整的内容。已要求忠实还原时，不重新发散风格。

单个组件的深化围绕主要操作和状态完成，在实际相邻内容中检验，不为突出组件建立与产品不相容的视觉系统。
