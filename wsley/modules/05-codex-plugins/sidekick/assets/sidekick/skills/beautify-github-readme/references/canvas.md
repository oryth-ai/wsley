# 内容与画布

## 项目叙事

首屏让读者识别项目、理解主要价值并看到可信证据。截图、真实输出、代码或机制图放在能支撑判断的位置，再介绍适用场景、工作方式和首次使用路径。

标题与主视觉可以共同呈现证据，也可以将短标题和较大的展示图分开，依据实际可读性选择。保留必要的命令、限制、兼容性、许可证与贡献入口，删除重复承诺和无助于采用的实现细节。

图片加载失败时，Markdown 标题、替代文字、命令与链接仍能表达主要信息。产品指标、比较和评价必须有实际依据，生成素材不能冒充产品截图或客户证据。

## 视觉语法

从项目的对象、行为、输出或工具特征推导主题，确定背景、前景、强调色、字体层级、线条、网格与空间关系。同一资源组保持共同语法，每个模块仍承担具体沟通职责。

技术工具可以采用终端、流程或结构表达，内容产品可以采用真实页面、作品或样本；主题来自事实，不从固定风格包套用。删除名称后仍能随意复用到任何项目的主视觉需要重新审视。

## GitHub 限制与阅读尺寸

准确正文、表格、链接和命令保持 Markdown。SVG 采用稳定 `viewBox`、适当的嵌入宽度与语义替代文字，不依赖脚本、`foreignObject`、远程字体或会被过滤的样式。

预览使用接近 GitHub 实际内容区的宽度，并查看窄屏缩放后的文字。`viewBox` 中的单位不是最终屏幕像素，必要标签过小时减少密度、拆分视觉或移到 Markdown，不靠放大原始画布证明可读。

明暗背景分别检查文字、边缘、透明区域和链接呈现。装饰性边框、阴影和标签有明确用途才保留，不用增加视觉模块数量衡量质量。
