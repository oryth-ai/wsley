# 页面与索引

## 发现与抓取

核对重要路由的真实状态码、可跟随的内部链接、robots 指令和 sitemap。sitemap 指向项目希望索引的规范 URL，排除失效、重复和不适合公开的地址。

区分 robots 抓取限制、页面或响应头的索引指令、认证与服务端授权。抓取被阻挡可能使爬虫无法读取页面上的 `noindex`，robots 也不是私有内容保护机制。

检查重定向链、循环、软 404、分页、参数与筛选组合，以及无入口的页面。抓取预算问题结合站点规模和真实日志判断，不把任意点击层数当作普适标准。

## 规范化与呈现

canonical、重定向、内部链接和 sitemap 传递一致的规范地址信号；实际被选为规范页的结果需要搜索数据核实。核对协议、域名、大小写、尾斜杠、参数和分页含义，不将所有分页都指向第一页。

标题与正文、主标题、品牌和页面类型一致，避免空标题、无意义模板重复与堆砌关键词。描述准确概括真实内容与价值，不承诺搜索引擎一定照原文展示。

主标题与分级体现内容关系，正文回答实际问题并提供可核对的依据。图片的替代文字服务于内容与可访问性，装饰图片保留适当空文本，不把所有图片都塞入关键词。

## 渲染与性能

分别取得响应头、原始 HTML 和需要时的浏览器渲染，检查关键内容、链接、canonical 和结构化数据是否按预期出现。不能用只提取正文的抓取工具断言脚本内容不存在。

移动视口保留主要内容、操作与链接。记录真实加载和交互条件，区分实验室诊断与现场用户数据；性能阈值以当前官方定义为准，单次 Lighthouse 分数不代表现场体验。

使用浏览器检查时复用 [agent-browser](../../agent-browser/SKILL.md) 的已安装工具。测试账户、外部验证服务和搜索平台使用当前授权，不为得分自动安装新工具或改动生产设置。

## 验证来源

涉及当前抓取、索引或结构化数据行为时，按实际问题核对 [Google Search 文档](https://developers.google.com/search/docs)。项目配置是否生效、搜索平台是否已重新处理与业务效果分别验证。
