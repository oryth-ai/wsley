# 性质与生成

## 断言的独立性

往返要求说明等价关系：规范化、浮点精度、时间格式、集合顺序和无效 Unicode 可能使逐字节相等并非真实契约。密码、压缩或序列化的逆关系在实际有效域内断言，不对未定义输入编造保证。

排序不仅保持长度，还应覆盖顺序、元素保留和已承诺的稳定性。金额、余额和资源限制优先验证守恒、边界与合法状态转移，不复制同一计算公式充当 oracle。

确定性与纯函数的恒真比较不同。函数可能读取时钟、遍历无序结构或依赖外部状态时，同一输入的重复结果是否相同需要由契约决定。

## 生成输入

把大小、范围、字符集和关系约束放进生成器。相关字段从同一来源派生，例如先生成列表再生成有效索引；避免独立生成后以大量 `assume` 或过滤条件筛选。

明确区分有效域、不合法但有规定拒绝行为的域，以及未定义行为。错误路径只捕获契约允许的异常或错误类别，其他崩溃、超时和资源失控应使测试失败。

为已知重要边界保留显式样例，例如空值、单元素、重复、零、负数、极值、非 ASCII 文本和临界时间。结合真实类型判断哪些输入成立，不机械把全部边界加到每个函数。

## 可测试结构

可以提取纯计算、为序列化提供对应解析器、用结构化中间表示替代拼接文本、返回结果替代不可见变更，或注入时钟与远程边界。只有这些变化同时改善职责或暴露真实契约时才实施。

已有普通测试足以证明低风险行为时保留现状。不把抽象接口、额外层次和纯函数拆分当成属性测试的固定前置工作。

## 工具与预算

采用项目实际支持的库和 runner，核对当前版本的生成、缩减与重放选项。Python、TypeScript、Rust、Java、Go 和智能合约工具的预算与状态模型不同，不搬用同一组参数。

样本数量、深度、时长和单次调用期限依据输入复杂度、真实依赖与项目预算设置。不要用低到几乎无覆盖的数量制造快速通过，也不要笼统关闭全部超时来掩盖死循环或慢依赖。

记录生成 seed、版本、配置及缩减后的最小反例。保留有回归价值的反例，并核对过滤和前置条件是否让有效样例接近零。
