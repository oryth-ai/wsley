# 目标与容量

## 测量定义

SLI 写明事件、计量单位、成功条件、测量来源、纳入与排除范围。延迟指标明确分位数或阈值内成功比例，异步工作明确排队、截止时间和最终交付；不能只计算 HTTP 2xx。

SLO 写明目标、窗口、适用人群或业务等级，以及缺失数据和低流量时的判断方式。滚动窗口、日历窗口、按请求与按时间计量分别说明，不能把一种预算直接换算成另一种事实。

## 错误预算

按事件计量时，允许失败比例为 `1 - SLO`，预算事件数为该比例乘以纳入的事件总数。燃烧率为实际失败比例除以允许失败比例；超出目标的延迟可以按目标定义计入失败。

多窗口告警同时观察长窗口的持续影响和短窗口的当前状态，阈值、窗口、预算消耗比例与处理时限共同推导。不能照抄固定燃烧率而忽略服务窗口和响应能力。

预算耗尽、快速燃烧与无有效数据分别有明确处理政策。发布节奏、例外批准和恢复条件由服务拥有者确定，技能不自行冻结或恢复生产发布。

## 容量与依赖

以实际到达率、工作时长、并发和队列测量建立容量模型，核对高峰、冷启动、突发流量和依赖故障。平均值不能覆盖尾延迟与相关性故障，压测夹具必须代表真实输入和资源限制。

显式预算连接、执行器、内存、存储、带宽和第三方配额。排队具有上限和截止时间，过载处理明确拒绝、降级与恢复行为；扩容触发条件应先于不可恢复积压。

超时、重试、并发重放和熔断共同核对。重试采用有界次数、退避与适用的随机抖动，不放大已故障依赖；结果未知时沿原业务事项确认，不创建重复交付。
