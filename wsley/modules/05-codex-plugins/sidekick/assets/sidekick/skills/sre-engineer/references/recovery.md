# 故障与运行责任

## 响应与恢复

依据用户影响与服务承诺确定事件范围、负责人和沟通渠道。保留时间线、观测与操作记录，区分已证实原因、候选原因和缓解措施。对外通知或升级联系按当前授权执行。

止损方案核对原事项、权限、业务状态和已发生的外部副作用。重启、回滚程序和恢复数据是不同操作，旧程序能否处理现有数据由支持契约决定，不靠临时兼容或清库掩盖问题。

RTO 和 RPO 分别说明恢复时限与可接受数据损失，覆盖数据库、对象、密钥、配置和未完成任务。恢复后验证实际用户任务、原事项关联、数量与权限一致性，不仅检查文件存在或进程启动。

## 演练与降级

先定义故障假设、范围、停止条件、观察指标和恢复步骤。优先使用隔离环境，实际故障注入和生产操作按用户与项目授权执行；没有执行时交付方案，不写成已验证。

覆盖当前契约支持的依赖断连、资源耗尽、进程退出、提交后丢失响应和恢复重放。降级仍须保留权限、计量与真实业务含义，不能用伪造成功维持可用性指标。

## 重复劳动与自动化

记录工作频率、耗时、风险和是否需要判断，再选择值得自动化的重复步骤。自动化明确输入、权限、幂等性、并发、审计和失败后的停止方式，先在可控范围验证。

运行手册连接到实际告警和恢复入口，沿用项目已有位置。复盘解释系统条件和可执行改进，保留真实责任，不把通用“无责”措辞当作无需分析具体控制缺口。
