# 边界与并发验证

## 真实依赖

读取正式 schema、队列与协议实现，复用项目已有集成入口。使用专用数据库、对象前缀和身份；清理只处理本场景拥有的资源。真实唯一约束、事务回滚、锁和提交可见性由数据库验证，不用预设 mock 返回值证明。

与副作用有关的流程，覆盖业务提交前失败、提交后响应丢失、同键重复、同键异参和实际支持的恢复入口。断言持久记录、原操作身份与最终结果，不只检查返回错误或调用次数。

需要完整进程生命周期的场景使用项目进程或镜像入口，保留启动、就绪、停止、退出状态及未完成责任的证据。避免每个断言都重新初始化环境；存在互相影响的状态时仍按场景隔离。

## 同步与退出

通过 channel、barrier 或可控依赖明确执行顺序，每个等待都有截止时间和失败诊断。开始工作、完成副作用、收到取消与退出是不同观察点，不用一个计数器代替全部状态。

取消发生后核对外部操作和持久责任，而非假定副作用没有发生。进程退出前结束自身持有的 goroutine 和服务；使用 `t.Cleanup` 时考虑后进先出的释放顺序。单个 goroutine 中的失败通过结果通道返回测试拥有者，不在辅助 goroutine 中调用 `t.Fatal`。

如果项目已经使用泄漏检测，区分预期的进程级 goroutine 与测试泄漏；不笼统忽略当前所有 goroutine 来消除失败。race detector 只证明本次执行未报告数据竞争，不证明所有调度顺序或业务并发语义正确。

## 不确定性与生成输入

为失败输入保留 seed、反例和相关版本，使问题可复现。区分错误性质、生成器缺陷和产品缺陷；避免用大量过滤条件使测试几乎没有有效输入。

属性应独立约束实现，例如余额守恒、上限、幂等性或序列化往返；不要重新计算同一算法来证明它自己。并发状态机测试覆盖受支持的操作序列和恢复责任，不引入项目已取消支持的历史格式。

## 临时资源

按项目约定放置临时文件、日志和必要证据；无专门约定时用测试原生临时目录。先关闭客户端、结束工作并等待退出，再清理资源。清理不能删除共享依赖、他人进程或非本轮数据。

隔离不足导致的失败修复隔离条件，产品缺陷修复实际实现；不要在测试中隐式重建缺失的业务事实或特权身份。
