# 算法与缓存

## 减少实际工作

用多种输入规模识别复杂度，检查嵌套扫描、重复查找、重复解析和不必要的对象转换。Map 索引的构造、额外内存、更新和失效都有成本，不将单次线性查找机械替换为一次新建的 map。

合并遍历、提前返回和批量处理要保持求值顺序、错误、副作用及结果顺序。减少调用次数若改变权限检查、事务边界或用户可见行为，就不是等价的局部性能优化。

正则、模板和静态解析结果确实可共享时，在合适拥有者处预处理。项目配置、租户和用户输入不同的结果不放入无区分的全局变量；初始化失败与更新责任仍遵循项目入口。

## 缓存契约

新增缓存前说明重复成本、命中场景、键、身份与租户范围、容量、时限和失效方式。授权条件、数据版本和时区等会影响结果的维度进入键或对应隔离边界，敏感结果不能跨用户复用。

缓存值采用明确的不可变或复制约定，避免调用者修改共享对象。错误缓存、负缓存和过期数据是否可用由实际契约决定，不能为了命中率把未知结果写成不存在或成功。

LRU、TTL 和其他策略只在对应访问模式下选择，关注热点、淘汰、清理和持续增长。缓存的锁、分配和后台任务同样需要资源预算；小数据集或低复用场景可能不值得增加缓存。

## 并发合并与失效

项目已有的 singleflight 等机制可以合并同键并发工作，但不等于跨请求缓存、业务幂等或分布式一致性。明确取消来自哪个调用者，底层工作何时停止，结果如何隔离，以及失败和迟到结果如何处理。

更新数据后按契约失效，检查旧请求的迟到写回会不会重新放入过期结果。跨进程缓存考虑实际一致性与失效传播，不从进程内去重推导全局唯一执行。

## 验证

分别测量冷启动、热命中、未命中、高基数、并发未命中和失效后的成本。验证身份切换、更新、取消、错误与容量边界；命中路径更快不能代替完整生命周期正确。

保留源系统为事实拥有者，缓存故障和过期处理遵循既有协议。依赖选择按项目实际需要，不为本技能默认新增缓存库、Redis、后台清理器或独立服务。
