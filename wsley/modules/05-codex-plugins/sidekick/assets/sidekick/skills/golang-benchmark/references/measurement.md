# 基准与比较

## 有效夹具

先定义一次操作的实际含义、输入分布和可观察结果，覆盖有关的规模、成功与拒绝路径。冷缓存、热缓存、初始化和稳态分别测量，不把重复命中内存对象的结果泛化为真实 I/O 性能。

准备工作和清理位于计时范围之外，除非它们就是被测契约的一部分。每轮需要重置的状态完整重置，写操作不会因为前一轮已经完成而变成空操作；同时控制数据库、网络和磁盘中的对象增长。

按项目实际 Go 版本选择 API。Go 1.24 起可用 `b.Loop()` 自动排除循环前的准备和循环后的清理；保持规范的 `for b.Loop()` 形式，不与 `b.N` 循环混用。已有 `b.N` 基准可继续沿用，核对 `ResetTimer`、结果消费及编译器消除；不为统一语法更换工具链。[Go 的 B.Loop 说明](https://go.dev/blog/testing-b-loop)

防止常量折叠、死代码消除、无效结果和过度理想化输入让实际工作消失。保护计时对象仍不等于夹具正确，需在计时外验证结果确实满足用例。包初始化和 `TestMain` 仍可能运行，`-run '^$'` 不代表完全没有初始化或外部副作用。

并发吞吐需要与实际资源模型对应。采用 `RunParallel` 等项目已有方式时，核对共享状态、每个 worker 的输入和收尾，报告并发配置；并发基准内部的工作并行，与同时运行两个互相干扰的候选基准是不同事项。

## 采集样本

以下命令中的包路径、benchmark 名称、时长及样本数量按实际场景替换。`task_dir` 为项目材料规则允许的独立任务目录的绝对路径；原始输出、二进制和 profile 均放在该目录。

```bash
go test -run '^$' -bench '^BenchmarkParse$' -benchmem -count 10 ./path/to/package > "$task_dir/before.txt"
```

切换到候选后，用相同命令与环境保存 `after.txt`。`-bench` 的名称按正则匹配，子基准按斜杠分段；限定对象时核对实际运行名称，避免意外把其他用例混进比较。

`ns/op`、`B/op` 和 `allocs/op` 含义不同。需要吞吐时报告真实处理字节或业务操作数；分配统计不包含所有 native/cgo 分配，也不等于进程 RSS。`-cpu` 改变 `GOMAXPROCS`，不能把不同并发配置的结果当作同一基准。

固定输入和随机种子，记录 Go、GOOS、GOARCH、CPU、构建标记、资源配额及依赖版本。候选依次运行；存在温度、频率、缓存或背景负载漂移时，使用同一条件交错采样或重建有效基线，保留完整样本，不挑选最快的一轮。

## 统计判断

```bash
benchstat "$task_dir/before.txt" "$task_dir/after.txt"
```

确认双方具有相同 benchmark 名称、参数和指标。读取中心估计、波动区间、样本数量和差异检验，分别说明统计证据和业务意义。改善一个指标时检查 CPU、内存、延迟与吞吐之间的交换，不能只保留最好看的结果。[benchstat 文档](https://pkg.go.dev/golang.org/x/perf/cmd/benchstat)

差异不显著、置信区间过宽和样本不足分别记录，不能写成已经提速，也不能据此证明等价。不同版本的 benchstat 展示格式与参数以实际帮助为准，不依赖某一个符号判断全部统计结论。

共享 CI 中的基准可能受到其他负载影响。先确定可重复的运行条件和合理预算，再按目标设置性能回归门槛；不自动修改宿主 CPU、内核、频率或容器限制来得到更低的数值。

## 证据保存

保留实际比较使用的原始样本、版本和命令，Profile 与二进制绑定到对应候选，后续修改不覆盖旧证据。测量日志和临时基准按项目材料规则管理；是否保留长期回归测试由真实用途决定，不强制每个源码文件另建基准文件。

计时失败时先检查进程退出码和诊断输出。若使用 `tee`，启用 `pipefail`，不能把日志写入成功当作基准成功。测量通过只支持相应场景，微基准改善仍需按目标验证真实用例和行为正确性。
