# Git Push

将当前分支推送到指定或已配置的远端。有未提交内容时，先使用 `git-review` 审计，再使用 `git-commit` 创建提交，完成后推送；工作区干净时直接推送已有提交。

仅在用户要求推送或明确调用本技能执行推送时运行。讨论、创建、安装本技能或仅加载其内容，不构成对当前仓库的提交或推送授权。

## 确定范围与目标

读取适用的 `AGENTS.md` 和仓库提交、推送约定，确认当前仓库、分支及 `git status --short`。未提交内容包括暂存区、工作区和未跟踪文件，不能只凭暂存区为空判断工作区干净。存在未解决冲突或尚未结束的合并、变基等操作时，先说明当前状态，不继续创建提交或推送。

在暂存或提交前确定推送目标。优先使用用户指定的远端与分支，否则依据当前分支的推送配置或上游确定唯一目标。首次推送时，远端唯一且同名分支目标清晰，可以建立上游；存在多个无法确定的目标、游离 HEAD 或没有可推送的提交时，只澄清实际缺口，不擅自选择其他仓库或分支。

推送范围是当前请求涉及的分支及其尚未推送的提交，包括此前已有的本地提交。用户明确排除某些提交，或范围存在实质歧义时，先解决该问题，不通过改写历史或扩大范围完成推送。

## 处理未提交内容

工作区干净时跳过审计和创建提交，不为执行本技能重新检查已完成的开发任务。

有未提交内容时，完整读取同级目录中的 `../git-review/SKILL.md` 和 `../git-commit/SKILL.md`。缺少必需技能时说明缺项并停止，不自行安装或用简化流程代替。按当前请求确定提交范围；保留明确排除的改动和其他任务的内容，不为清空工作区而一并提交。

先按 `git-review` 完成规范与结构审计，处理已授权的必要修正并完成相应验证，再按 `git-commit` 暂存并创建一个或多个原子提交。审计有尚未处理的必须修正问题、必要验证失败或提交失败时，停止后续推送，不退回到推送旧提交来掩盖未完成的流程。

提交后核对最终状态与实际提交内容。新出现的未审计变更不能自动混入提交；若审计后已无可提交内容，则推送已有提交，不创建空提交。具体审计方法和提交规范由对应技能负责，本技能不另设一套规则。

## 推送与结果

核对当前分支、目标和待推送提交范围后，使用普通推送，只更新已确定的分支；需要明确限制范围时使用 `git push <remote> HEAD:refs/heads/<branch>`。首次推送可加 `--set-upstream`。不扩大为推送全部分支、标签或镜像，不强制推送、绕过 hooks 或自动改写历史。

推送被远端领先、分叉或分支规则拒绝时，说明原因并停止，不为完成推送自行合并、变基或绕过限制。认证或网络失败时可排查并重试有明确恢复依据的操作；问题未解决则报告实际失败，保留已创建的本地提交，不循环重试或宣称已同步。

推送成功后核对远端目标分支与预期提交一致，检查工作区状态，简要报告审计结果、新建提交、实际推送的远端与分支，以及仍保留的改动。工作区干净而直接推送时，无须补做或虚构审计、提交步骤。
