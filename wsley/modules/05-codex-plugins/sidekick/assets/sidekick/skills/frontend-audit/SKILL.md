# Frontend Audit

以真实界面、使用者任务、项目契约和实现证据评审现有前端或界面变更。承担设计评议、产品体验与 Web 实现审查，按请求选择深度；区分设计建议、已确认问题和已验证修复。

## 范围与依据

确认对象、使用者、主要任务和交付模式。只要求审查、分析或建议时保持只读，明确要求优化或修复时在授权范围内实施。读取适用规范、权威产品资料、代表页面与已确认设计方向；实现用于核对现状，不能自行推翻用户要求。

| 请求范围 | 审查方式 |
| --- | --- |
| 视觉评议、设计完成度或模板感诊断 | 检查页面目的、构图、层级、材料与整体性格，再说明具体差距及改善方向 |
| 页面、流程、应用或整站体验 | 沿角色、入口、任务和状态核对结构、操作与结果 |
| 语义、表单、导航、响应式或资源加载等实现问题 | 采用 [Web 实现检查](references/implementation.md)，选择相关条目和运行证据 |
| 待提交内容、提交区间、分支或 PR 的界面影响 | 采用 [变更审查](references/change-review.md) 确定比较对象，追踪增删及消费者 |
| 目录、代码组织、内容风格与项目规范 | 使用 [git-review](../git-review/SKILL.md)，保持与产品体验审查的职责区分 |

局部审查覆盖所属任务与相邻影响，共享问题沿调用方展开；整站审查梳理页面、布局、导航和关键流程。代表页面可以证明共享机制，不能代替其他页面的信息与行为覆盖。说明尚未检查部分，不因一次变更默认审查整个应用。

## 产品任务与结构

从真实角色、对象与场景确定页面需要支持的决策、操作和成功条件，区分首次使用、日常处理、调查核对和异常恢复。沿导航、路由、权限及数据来源检查：

- 功能区和页面是否有清楚职责，对象是否有主责详情，返回、刷新和直接链接是否保留合法上下文
- 信息是否支持识别对象、判断状态、采取行动与核对结果，概览是否指向有意义的下一步
- 文案、界面对象和业务概念是否一致，是否将接口或内部模块直接暴露为用户的心智负担
- 初次使用是否有起点，帮助是否位于实际困难附近，公开页面是否表达真实价值、证据与行动

将缺少产品依据的建议标为假设，代码和截图不能证明用户偏好，不编造研究结果、用户评价或转化提升。不同应用按自身目的评估，不强制统一主题或组件体系。

## 视觉质量与表达

判断当前页面需要说服、操作、阅读还是展示。核对真实内容是否成为主体，空间是否有主次、分组与节奏，字体、色彩、图像、表面和运动是否共同表达选定方向。风格成立与实现精细分别评估，功能可用不能代替视觉完成度。

把“平铺”“廉价”“模板感”转成位置、表现和影响：区域等权、缺少焦点、产品材料不足、字号与密度不符、重复容器掩盖关系，或细节没有统一规则。先识别结构与共同原因，再判断局部处理；不能只批评装饰过多，也要指出视觉投入不足、主体缺席和表达过弱。

具体方法按需要读取 impeccable 的 [布局](../impeccable/references/layout.md)、[排版](../impeccable/references/typography.md)、[色彩](../impeccable/references/color-and-theme.md)、[材料](../impeccable/references/imagery.md) 与 [动效](../impeccable/references/motion-and-surfaces.md)。[精修与强化](../impeccable/references/interface-refinement.md) 帮助选择改动深度，只读评议仍交付建议。

风格与控件本身不决定缺陷。表格、卡片、渐变、衬线或居中布局按其作用判断，不用审美禁令、固定数量或任意评分制造问题；用户选定方向是评审依据，不能因为更偏好另一种风格就要求换品牌。

## 信息、操作与状态

选择信息载体时核对真实关系：同构比较与批量操作、单个对象详情、编辑、时间顺序、趋势与分布分别组织。图表保留真实单位、基线、时间范围与必要精确值，缺失和未知不能补成零。精简仍保留识别、决策、计量、确认和恢复的依据。

核对主次动作、搜索筛选、排序分页、选择范围、只读和编辑。对象、成本与影响在提交前可见，已保存结果、草稿和后台刷新边界明确。语义、表单、路由、焦点和响应式的具体检查采用 [Web 实现检查](references/implementation.md)。

按流程覆盖适用的加载、有效空结果、部分失败、失权、提交中、已受理、结果未知、业务失败、完成及完成后读取失败。后续读取失败不能反推提交失败；短时通知消失后，待处理结果与恢复身份仍然可找。

## 生产质量

根据实际范围选择维度，不将完整清单套用到每个局部请求：

| 维度 | 核对重点 |
| --- | --- |
| 内容与国际化 | 术语、动作、错误下一步、语言资源、复数、地区格式和长文本 |
| 访问与适配 | 实际视口、缩放、键盘、焦点、读屏、触摸、对比和减少动态效果 |
| 可靠性与数据 | 重复请求、弱网、中断、迟到响应、草稿、原事项恢复、精度、单位和更新时间 |
| 安全与隐私 | 服务端授权、身份范围、私有缓存、敏感输入输出和埋点 |
| 性能与资源 | 请求瀑布、重复读取、字体与图片、大列表、图表、布局偏移和真实交互耗时 |
| 运营与增长 | 首次成果、支持入口、公开页面可发现性、故障发现与真实任务效果 |

界面显隐不替代服务端授权。修复不能暗改身份、操作目标、条款或恢复语义，沿受影响调用链核对契约。性能收益和用户效果分别需要测量依据。

## 发现、整改与验证

每项发现连接角色与任务、具体位置、触发条件、观察证据、实际影响和建议。区分可复现缺陷、契约冲突、设计风险与可选改善；变更审查另行区分新增、回归和原有问题。同根因的多处表现合并，说明受影响消费者与不同后果。

优先级来自影响、范围与可恢复性。先处理阻断任务、错误结果、失权数据与不可恢复状态，再安排效率和视觉改善；问题类型不自动对应固定严重级别。证据不足时说明待确认条件，没有固定发现数量或必报分数。

已经授权整改时，沿发现与依赖修复共同原因，设计和视觉实现采用 [impeccable](../impeccable/SKILL.md)，组件、状态和运行证据直接承接。只读评审不自行创建实现、原型或新方向。工程修改采用 [disciplined-dev](../disciplined-dev/SKILL.md)。

取得目标版本的实际画面与操作证据，必要时使用 [组件状态与压力验证](../impeccable/references/component-states.md) 稳定分支，区分夹具与真实业务。修改稳定后集中复核原问题、相关消费者及新影响；已有有效结果复用，不重复启动整站审计。

交付主要发现或改进、依据、优先级、实际覆盖与验证限制。自动扫描不能证明完整可访问性，静态检查不能证明视觉质量；无法运行、截图过期和缺少基线时明确限制。材料保存采用项目约定，不默认创建长期报告或平行事实来源。

## 专项协作

仅在具体问题需要时采用相关能力，将项目约束、发现和有效证据交给对应技能：

| 问题 | 采用的能力 |
| --- | --- |
| 用户需求与使用行为缺少证据 | [user-research](../user-research/SKILL.md) |
| 需要设计、重设计或视觉整改 | [impeccable](../impeccable/SKILL.md) |
| shadcn 的接口、组合、主题或本地定制 | [shadcn](../shadcn/SKILL.md) |
| 键盘、语义、焦点或辅助技术障碍 | [accessibility](../accessibility/SKILL.md) |
| 措辞、术语或本地化 | [ux-copy](../ux-copy/SKILL.md)、[i18n-expert](../i18n-expert/SKILL.md) |
| React 加载、渲染与交互性能 | [vercel-react-best-practices](../vercel-react-best-practices/SKILL.md) |
| 公开页面的抓取、索引与搜索呈现 | [seo-audit](../seo-audit/SKILL.md) |
| 实际页面操作与浏览器证据 | [agent-browser](../agent-browser/SKILL.md) |

专项检查保持当前只读或整改范围，不自动安装依赖、接入服务或展开全部专项流程。
