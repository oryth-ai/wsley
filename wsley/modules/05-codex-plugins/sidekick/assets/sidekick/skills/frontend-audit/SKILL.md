# Frontend Audit

从使用者完成任务的过程审查现有前端，以实际界面、调用链和项目事实提出可执行的改进。设计建议、已确认的问题和已验证的修复分别交付。

## 范围与依据

先确认审计对象、使用者、主要任务和交付模式。仅要求审查、分析或方案时保持只读；明确要求优化或修复时，在授权范围内完成实施和验证。关键业务条件或设计取向无法确定时澄清对应缺口，继续其他独立工作。

读取适用项目规范和权威产品资料，保留用户已确认的技术栈、视觉方向和业务边界。实现用于核对现状，不能仅凭现有页面推翻已确认要求。不同应用分别按其任务评估，不强制统一主题、布局或组件库。

审计深度随范围调整：单个区域追踪所属任务及相邻影响；跨页面问题检查共享组件和全部调用方；整站审计先盘点页面、布局、导航、入口和关键流程，标明已检查及尚未覆盖部分。代表页面可用于验证共享规则，但不能代替其余页面的信息和行为审查。

## 任务与结构

从真实角色、对象和使用场景判断页面需要支持什么决策及操作。核对使用频率、进入条件、主要输入、结果、后续动作和可观察的成功标准；区分首次使用、日常操作、调查核对和异常恢复。

沿导航、路由、权限及数据来源检查：

- 页面及功能分区是否各有明确职责，同一对象是否有清楚的主责详情；入口、页签、返回、刷新和直接链接是否保留合法上下文
- 信息是否按识别对象、判断状态、采取行动及核对结果组织；概览能否指向下一步，详情是否保留做决定的依据
- 文案、界面对象与业务概念是否一致，是否将内部模块、接口或数据库字段直接变成用户需要理解的产品结构
- 初次使用是否有可执行的起点，帮助是否出现在实际困难附近；公开页面是否清楚表达价值、价格、信任信息及行动入口

将缺少产品依据的建议标为假设。代码、截图和模拟操作不能证明真实用户偏好，不编造访谈、使用指标或研究结论。

## 页面、功能区与组件

逐项判断信息和控件对当前任务的作用。精简时保留识别、决策、计量、确认和恢复所需内容；业务核对编号、单位、时间范围及危险操作影响按实际用途呈现，不按字段类型机械删除或隐藏。

按信息关系选择载体：同构记录比较与批量处理适合表格，单个对象资料适合语义字段，编辑适合分组表单，事件顺序适合时间线，趋势及分布适合相应图表。图表保留真实单位、基线和可访问的精确值，缺失和未知不能补成零。不以减少表格、增加卡片或引入依赖的数量衡量改进。

核对主次动作、搜索筛选、排序分页、选择范围、只读和编辑状态。确认对象、输入、成本及影响在提交前可见；已保存结果、未提交草稿和后台刷新各有清楚边界。

按所属流程覆盖实际适用的状态：首次加载、有效空结果、部分读取失败、失权、提交中、已受理、结果未知、业务失败、完成及完成后读取失败。短时通知用于无需持续处理的反馈，待处理状态保留可发现的原地入口；提示消失不能成为业务结果或恢复身份丢失的原因。

检查文字层级、密度、对齐、字体、颜色、主题、图标和交互反馈是否形成一致的应用内语法。控件选择服从任务和设备，优先复用适当组件；引入第三方依赖时核对适用范围、维护成本和现有工具链。

## 生产质量

根据任务涉及的部分检查下列维度，不把所有项目机械套用到每次局部审计：

| 维度 | 核对重点 |
| --- | --- |
| 内容与国际化 | 术语、操作结果、错误下一步、语言资源、复数、地区格式、长文本和辅助技术标签 |
| 布局与访问 | 实际视口、缩放、局部溢出、触摸目标、键盘路径、焦点、读屏、对比度及减少动态效果 |
| 可靠性 | 重复操作、弱网、中断、冲突、身份及范围变化、迟到响应、原事项恢复和草稿保留 |
| 数据与信任 | 金额和数量精度、单位、更新时间、完整或部分范围、研究证据及可解释性 |
| 安全与隐私 | 服务端授权、私有缓存隔离、敏感输入、上传下载、错误披露与埋点内容 |
| 性能 | 请求瀑布、重复查询、路由及资源加载、大列表、图表和实际交互耗时 |
| 运营与增长 | 首次成果路径、支持入口、公开页面可发现性、线上故障发现和任务效果指标 |

界面显隐不代替服务端授权。修复不得隐式改变身份、操作目标、商业条款或恢复语义；沿受影响调用链核对所需契约。

## 发现与修复

每项发现写明受影响的角色和任务、具体页面或代码位置、触发条件、观察证据、实际影响及建议。把可复现缺陷、契约冲突、设计风险和可选改进分开，优先处理任务阻断、错误结果、失权数据及不可恢复状态，再处理效率和视觉问题。没有证据时说明待确认条件，不用审美偏好制造缺陷。

只读审计交付发现、优先级和建议。审计并修复时，先解决影响相关页面的共同原因，再处理局部差异；同步调用方、资源、本地化和必要验证。保持获批方向，在同一实现中完成修正，不额外维护未经请求的原型。

仅对会实质改变设计判断的方案给出备选及取舍，不为凑数量列方向。记录未覆盖范围和仍依赖用户或环境的事项，不以静态检查通过替代产品体验结论。

## 验证与交付

可运行时先取得相关页面和状态的实际证据，修改稳定后集中验证受影响流程。视觉变化查看目标视口及适用主题；交互变化实际操作成功、失败和恢复路径；共享组件核对相关调用场景及键盘行为。复用仍有效的证据，不随每次局部修改重跑全量验收。

按风险和影响选择格式、类型、静态、组件及浏览器检查。涉及业务写入的验证采用已授权身份和隔离数据；浏览器、研究或外部工具的可用性不扩大操作权限。

无法运行、截图过期或数据来自受控夹具时明确验证限制。自动扫描覆盖其可检测问题，不能证明完整可访问性；没有真实性能测量时不宣称性能已改善。独立评审按用户要求及实际授权安排，复审优先核对原发现、修复结果及其引入的影响。

交付先说明主要发现或改进、受影响任务及证据，再说明验证、剩余问题和覆盖范围。使用有依据的优先级；只有用户要求且存在明确评价方法时才给总体评分。任务材料、截图及长期文档遵守所属项目的保存约定，不自动建立平行事实来源。

## 专项能力

需要专项知识时按需读取本插件的对应技能：用户研究采用 [user-research](../user-research/SKILL.md)，文案采用 [ux-copy](../ux-copy/SKILL.md)，视觉判断采用 [oil-ui](../oil-ui/SKILL.md)，界面规则采用 [web-design-guidelines](../web-design-guidelines/SKILL.md)，可访问性采用 [accessibility](../accessibility/SKILL.md)，React 性能采用 [vercel-react-best-practices](../vercel-react-best-practices/SKILL.md)，国际化采用 [i18n-expert](../i18n-expert/SKILL.md)，公开页面 SEO 采用 [seo-audit](../seo-audit/SKILL.md)。

实际浏览器操作可使用 [agent-browser](../agent-browser/SKILL.md)；实施遵循项目开发规范及适用的 [disciplined-dev](../disciplined-dev/SKILL.md)。专项规则须与项目技术栈、权威事实和任务范围核对，只加载相关能力，不因开展审计自动安装依赖、接入服务或执行全部专项流程。
