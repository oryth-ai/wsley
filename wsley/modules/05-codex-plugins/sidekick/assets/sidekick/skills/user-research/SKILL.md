# User Research

围绕需要做出的产品决定设计研究，把真实观察转为可追溯的发现。研究计划、招募材料、执行支持和已有资料分析分别按请求交付，不把计划写成已经完成的研究。

## 问题与方法

读取项目已有的用户定义、产品目标、研究资料和相关界面，确认当前决策、证据缺口、参与者范围及实际可用的时间与渠道。已有答案直接复用，关键条件缺失时再澄清。

| 证据缺口 | 适用方法 | 需要保留的限制 |
| --- | --- | --- |
| 工作背景、动机、替代方法与困难 | 半结构访谈、情境观察 | 自述与观察分别记录，不据少量访谈推断人群比例 |
| 已有界面的任务障碍 | 可用性测试 | 任务、原型完整度、设备与主持方式会影响结果 |
| 人群分布、态度或偏好 | 问卷 | 招募偏差、样本框、问题措辞与未回应者影响结论 |
| 分类、导航与信息组织 | 卡片分类、树测试 | 样本应覆盖实际术语和任务，不将分组偏好直接当作最终导航 |
| 长期或跨场景行为 | 日记研究、重复观察 | 参与负担、遗漏和回忆偏差需要说明 |
| 两个方案对业务指标的因果影响 | 随机对照实验 | 先定义指标、分配、样本量和停止规则，不能靠临时显著性挑结果 |

按决策风险、用户差异、研究方法和实际预算确定人数与时长，不把上游示例中的样本数当成通用门槛。定性研究用于发现和理解问题，比例、总体差异与因果结论需要对应设计。

## 准备与执行

把研究问题改写成中性的任务和开放式问题。访谈先建立背景，再请参与者描述最近发生的具体经历，追问动作、理由和结果；概念反应与现有行为分开，避免诱导、推销和假设性承诺。

可用性任务描述目标与情境，不透露按钮、页面或期望路径。记录完成情况、误操作、犹豫、求助及恢复，区分参与者自行完成与主持人提示后的完成。原型未实现的部分不能记为用户失败。

使用真实参与者资料前核对同意范围、录音录像、访问权限、保存与删除约定。联系参与者、发送问卷或接入研究平台按当前授权执行；技能本身不提供这些操作的授权。

## 综合与交付

先整理逐项观察，再做主题聚类、任务旅程或工作动机分析。每项发现连接到原始片段或记录，说明受影响人群、任务、触发情境、重复表现和反例。原话、转述、研究者解释与设计建议保持可区分。

以实际影响和证据强度安排建议，明确下一步是设计、实现、补充研究还是暂不调整。使用 [oil-ui](../oil-ui/SKILL.md) 衔接界面方向，使用 [ux-copy](../ux-copy/SKILL.md) 衔接措辞问题；研究结果不自动授权修改产品。

交付请求所需的研究计划、问题提纲或综合发现，说明样本、方法、真实执行范围及未解决的问题。模拟人物、合成回答和桌面推演明确作为设计材料，不冒充用户证据。
