# Security and Hardening

围绕实际攻击面、资产和信任边界评审安全。读取适用的项目规则，修改前遵循 [disciplined-dev](../disciplined-dev/SKILL.md)。根据用户目标执行审计或整改，保留已明确的授权；只有缺失的关键产品选择或执行权限才需要确认。

## 威胁与证据

从受影响入口追踪输入来源、权限、数据存储、远程调用和副作用，识别凭据、个人数据、资金、管理操作及客户内容等资产。核实参数实际由谁控制，不能因为值来自数据库、配置、进程环境、任务或模型输出就认定可信。

按冒用、篡改、抵赖、泄露、拒绝服务和提权检查相关边界，为正常用例补充实际可触发的滥用场景。考虑框架、中间件、数据库和代理已有的控制，再判断是否存在缺陷。

报告具体入口、攻击者能力、控制缺口、代码路径和影响。已登录路径仍需检查越权，不能因需要登录就排除。理论风险和无法确认的数据流标为待核实，不将关键词匹配直接定性为可利用漏洞。

## 身份与权限

- 沿用项目实际支持的密码、会话、OIDC、令牌和服务凭据协议，核对生成、存储、轮换、失效与恢复
- 核对主体、动作、对象、租户、业务状态与字段权限；界面隐藏和身份验证成功不能代替服务端对象授权
- 密码采用项目认可的密码哈希与参数，秘密按规定的配置或密钥机制读取，不引入第二份明文副本
- Cookie 的域、路径、持久性、`HttpOnly`、`Secure`、`SameSite` 与 CSRF 防护共同验证，取值由实际跨站流程决定
- 登录、验证、找回及昂贵接口具有符合实际进程拓扑的防滥用控制，不硬编码统一限流阈值

## 输入、响应与副作用

- 在信任边界校验结构、大小、类型与业务许可；SQL 参数化，命令采用明确参数传递，输出按目标上下文编码
- 上传核对内容、大小、解压预算、存放与交付权限，不以文件扩展名证明安全
- 用户影响的外部 URL 核对协议、目标、DNS 结果、重定向与实际连接地址；根据业务允许的网络范围防止 SSRF 和 DNS 重绑定
- 文件删除、移动和覆盖在操作前核对实际解析路径、允许根目录和资源归属，处理符号链接与检查执行间竞争；拒绝后不扩大目标范围
- 支付回调、Webhook 与内部接口核对签名、时效、身份、重复及原事项绑定，不信任浏览器宣告的支付或授权结果
- 响应仅包含允许字段，异常不泄露内部堆栈与秘密；CORS 和安全响应头符合真实 origin、代理与内容需求

## 数据、依赖与模型

个人数据按实际用途和适用要求管理收集、访问、导出、删除及保留。核对数据库、对象、缓存、备份和分析副本的完整生命周期，业务历史与审计保留遵循项目契约，不把删除账号等同于销毁所有记录。

复用项目权威锁文件、包管理器、安装脚本策略和原生审计入口。结合运行、构建与部署可达性判断依赖告警，不自动强制升级、重写锁文件或批准全部安装脚本。安全扫描结果是证据之一，不单独证明包安全或恶意。

模型输入、输出及检索内容作为不可信数据处理，工具权限和资源隔离由代码执行。核对跨租户上下文、敏感字段、执行参数、输出编码与资源预算，不把提示词当作权限边界。

## 验证与交付

按真实攻击路径验证输入拒绝、对象授权、跨租户访问、会话失效、签名及副作用边界。脱敏输出必要证据，避免在报告、日志或测试产物中复制秘密。

交付已证实问题、触发条件、影响和对应修复证据，区分尚未验证的路径。安全变更的实现、测试、配置、生成物与交付资源保持一致，不把一份通用清单的完成当作产品安全结论。
