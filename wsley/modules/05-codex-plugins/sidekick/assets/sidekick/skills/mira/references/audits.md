# 审计与整改

适用于用户要求系统评审前端、后端或一条完整业务流程的任务。先确定只读审计还是审计并整改，以及评审对象、必须保留的行为和完成条件。

## 组织评审

以前端产品任务、信息架构、交互和视觉体验为主时使用 [frontend-audit](../../frontend-audit/SKILL.md)；以后端业务不变量、权限、数据与运行责任为主时使用 [backend-audit](../../backend-audit/SKILL.md)。待提交改动的目录、代码组织和项目规范审计使用 [git-review](../../git-review/SKILL.md)，不以其中任一种审计替代另外两种。

跨端任务围绕用户流程组织：前端收集入口、输入、状态和反馈证据，后端追踪契约、事务、异步责任和恢复；在共同边界上核对权限、错误、重复请求和未知结果。一个问题涉及两端时合并根因与修复责任，避免分别产出相互冲突的方案。

各审计技能按问题选择相关内部能力。本技能接续其发现和决定，不再启动一轮重复的完整专项审计。

## 衔接整改

将每项需要处理的问题连接到证据、违反的要求、影响、责任位置和验收场景，区分已证实缺陷、待核实风险与可选建议。按实际影响和依赖安排整改，保持同一问题的修复范围与完成条件一致。

只读任务交付发现和建议。用户已经要求整改时，带着问题依据进入 [development.md](development.md)，完成实现、调用方和验证的同步调整；无需另行请求已明确范围内的实施授权。

整改后复核受影响的场景和规范，保留仍有效的其他审计结论。新改动引起关联问题时扩大到必要范围，不因进入实施而重新审计未变化的整个系统。

## 汇总结果

按影响合并有关发现，说明已完成整改、有效证据、未覆盖范围及仍需决定的问题。按项目约定在对话或已有材料中承接结果，不默认新建长期审计文档或固定目录。
