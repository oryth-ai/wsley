# 数据与资源

## 并行与流式交付

廉价同步条件能够排除工作时，先判断再等待昂贵调用。只在确实消费结果的分支 `await`，避免无用请求及首屏等待；不能把权限检查推迟到副作用之后。

独立操作尽早启动并集中等待，存在依赖的操作按依赖图组织。每个 promise 有错误与取消责任，不能因使用 `Promise.all` 就无限增加请求并发或遗失失败。

API 路由和组件在获得必要输入后启动工作，推迟到使用点才等待。列表中的逐项依赖可以各自衔接，避免人为把全部第一阶段完成设为第二阶段的统一屏障。

根据内容与用户任务安排 Suspense 和流式边界，让独立部分尽早呈现。骨架、错误和完成反馈保留真实语义，不用流式输出掩盖权限、事务或关键数据尚未确定。

## 服务端边界

服务端动作与接口一样验证调用者、对象和业务状态，不能信任客户端传入身份。RSC 与 SSR 不在模块级可变对象中保存用户请求状态，避免跨请求数据泄露。

请求内去重采用实际支持的请求作用域机制；跨请求缓存具有明确键、身份与租户范围、失效、时限和容量。`React.cache`、LRU 与框架数据缓存的作用域不同，不能互相替代。

向客户端只序列化所需字段，核对敏感信息、重复结构与额外对象包装造成的传输。服务端组件边界可以调整数据获取并行性，但不能因此把必要授权或数据库事务拆散。

真正静态且不包含请求身份的字体、标志和固定 I/O 可以移出请求路径；初始化失败、配置加载和资源生命周期仍遵循项目入口。响应后的非阻塞钩子只承担适合该运行时的工作，持久交付不能依赖进程内回调。

## 包体与加载

根据真实打包结果判断 barrel 导入、动态路径与文件系统访问是否扩大依赖范围。优先使用可被构建器分析的路径和有效导出，不为追求直接导入破坏包的公开接口。

重型组件、编辑器、图表和可选能力按实际启用时机拆分。动态导入、条件加载和框架懒加载核对 SSR、错误边界、布局占位与可访问性，不能只把成本移动到用户操作最关键的时刻。

第三方分析和非关键脚本按需要延后，不阻断必要的首屏交互。hover 或 focus 预加载需要真实使用概率与资源预算，不给每个链接无条件预加载整个应用。

资源提示、脚本 `defer` 与 `async` 按顺序依赖和实际浏览器语义选择。关键图片、字体和脚本的优先级共同测量，避免过度预加载导致竞争。
