# 状态与渲染

## 订阅与更新

只为渲染真正需要的值订阅状态，回调执行时才使用的值可在适当边界读取。派生布尔值或局部选择器应能减少无关更新，不订阅整个大对象后再丢弃大部分字段。

能从当前输入直接计算的状态在渲染中派生，不用 Effect 复制一份状态。用户操作引起的业务动作放在事件边界，Effect 负责与外部系统的适用同步，避免重复执行与依赖循环。

基于旧状态更新时采用合适的函数式更新；昂贵的初始值按实际 API 使用惰性初始化。临时、高频且不影响渲染的数据可以使用 ref，但不能把应可见的变化藏在 ref 中。

拆分具有独立依赖和生命周期的 hook，避免一个组合 hook 让所有消费者订阅无关变化。组件定义保持稳定，不在父组件渲染时重新定义组件类型导致子树重建与状态丢失。

## 引用与记忆化

昂贵计算或组件经测量确有收益时再 memo，简单表达式不为形式统一包装。依赖列表反映实际读取的值，不能通过漏写依赖得到过期数据。

默认对象、数组和回调的引用稳定性按需要处理，静态默认值可放在合理的共享位置。不能用可变全局缓存保存请求或用户状态，也不为每个字面量制造模块级变量。

稳定回调、事件 ref、useLatest 或 Effect Event 解决不同问题，按项目版本和生命周期选择。不能通过读取最新值掩盖原事项本应保留的身份，也不能机械将不受支持的 API 加入项目。

## 响应与呈现

将非紧急渲染与当前输入响应区分，按实际版本使用 Transition 或 deferred value。等待、提交中与后台渲染的反馈分别表达，不把 transition 状态当作业务完成标志。

长列表、屏外内容和复杂子树按测量使用虚拟化、`content-visibility` 或适用的保留状态机制。核对布局尺寸、查找、焦点与读屏行为，不让优化移除必要内容或恢复状态。

静态 JSX 可以移到合适位置；SVG 动画、外层变换和坐标精度按真实渲染器与视觉要求判断。条件渲染明确处理 `0` 等可能被意外显示的值，不能仅凭语法偏好重写全部条件。

## Hydration 与浏览器状态

服务端首屏与客户端首次渲染尽可能一致。主题、存储和时间等仅客户端数据需要明确初始化与防闪烁方案，核对 CSP、隐私和脚本加载顺序。

预期差异的警告抑制应范围明确，不能用 `suppressHydrationWarning` 掩盖错误结构或真实数据冲突。隐藏与保留组件状态的 API 按实际版本核验，重新显示后焦点、订阅和资源生命周期仍正确。
