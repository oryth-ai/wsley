# 客户端成本

## 请求与事件

使用项目已有查询层处理重复请求、缓存、取消和失效，不为去重默认引入 SWR 等新库。缓存键包含会改变结果的身份与范围，切换用户后不能复用旧私有数据。

共享事件监听由明确拥有者注册和解除。不会阻止默认行为的滚动等监听可采用适当的 passive 选项；需要 `preventDefault` 的路径不能机械设置为 passive。

浏览器存储有大小、格式、版本与访问成本约束，只保存必要数据并处理失效或异常。缓存存储读取需要正确的更新与跨标签同步，不把存储内容当作可信身份或永久事实。

## 计算与 DOM

针对已测量的热点，重复查找可建立适当的 Map 或 Set，循环中稳定的属性和计算可在合理范围复用。额外缓存的构造、内存和失效成本也要计入，不把微优化推广到全部代码。

可以在不改变求值和错误语义时合并遍历、提前返回、先检查长度或用线性遍历求极值。`flatMap`、不可变排序等 API 需要符合项目运行时支持范围，不为使用新语法增加兼容层。

正则、稳定对象和结果缓存根据作用域及线程安全选择，带状态正则的 `lastIndex` 不能被意外共享。缓存键和生命周期完整，避免无界 Map 或跨用户共享结果。

DOM 读取与写入合理分组，样式变化优先通过合适的 class 和批量更新表达，减少强制同步布局。不能用减少 DOM 操作的理由破坏交互顺序或中间可见状态。

## 空闲与初始化

非关键工作可按支持情况延后到浏览器空闲或合适调度点，明确最长等待、取消及页面退出行为。关键提交、权限和持久交付不依赖空闲回调。

应用级初始化由明确入口拥有，考虑多入口、热更新、SSR 与资源关闭，不用任意全局布尔值掩盖重复装配或跨请求状态。高级优化仍以实际性能和完整行为证据验收。
