# 查询与运行

## 索引与访问

围绕真实谓词、连接、排序与返回范围选择索引。复合索引考虑列顺序和选择性，部分索引的谓词应能被实际查询利用，覆盖索引的额外空间和写入成本需要测量。

B-tree、GIN、GiST 等索引类型匹配真实操作符与数据类型，不能把一种索引当作所有查询的加速器。JSONB、全文搜索与向量功能使用项目实际扩展和操作符类，核对索引是否真正命中。

避免逐条查询形成 N+1，批量读取仍要控制结果体积与内存。分页需要稳定排序和可重复的边界，大偏移场景评估游标或键集分页，保留产品要求的计数、跳页和排序语义。

## 连接与执行

连接预算覆盖所有进程、任务、管理入口和部署重叠，连接池具有实际上限、等待期限和关闭责任。不能通过无限增加 `max_connections` 解决无界并发。

会话池、事务池与预备语句、临时表、会话变量和锁的兼容性按实际代理及版本核对。空闲事务、连接泄漏和失效会话需要显式处理，客户端超时不代表服务端查询已停止。

## 计划与维护

比较估算与实际行数、扫描、连接方式、排序、缓存命中和 I/O，结合真实参数判断计划。示例中的固定耗时和加速比例不作为验收目标。

使用项目已有统计视图和 `pg_stat_statements` 等可用扩展定位主要成本；没有安装时不为一次审查默认改动数据库。统计信息与数据分布变化可能改变计划，测量记录版本、规模和运行条件。

核对 autovacuum、长事务、膨胀、分析统计及维护预算。索引和表维护考虑锁、磁盘、复制与业务时段，不能从“优化查询”推导对生产执行重建或清理的授权。
