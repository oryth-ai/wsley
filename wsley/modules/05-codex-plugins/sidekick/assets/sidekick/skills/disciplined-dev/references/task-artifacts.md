# 任务材料组织

## 保存条件与归属

计划、进度和交接通过对话、宿主任务状态或协作消息承接。只有用户要求文件、工具确需文件或明确的后续步骤无法通过这些渠道有效承接时才保存材料；先确定用途、消费者和保留条件，再创建路径。纯阅读、终端输出、任务复杂或可能发生上下文压缩都不构成建目录的理由。

Sidekick 自主管理的任务材料默认放在所属仓库根目录 `.sidekick/`。用户指定的交付位置和项目明确规定的任务材料根优先，采用它们时仍保持下述任务与运行分层；正式源码、项目文档、构建产物和运行配置按各自职责管理。不将材料写入无关仓库、插件或技能目录。

## 一个任务一个根目录

首次确需保存材料时创建 `.sidekick/YYYYMMDDHHmm-<task>/`。时间采用创建时的本地时间，任务标识使用简短、有含义的小写 kebab-case，不含路径分隔符或 `..`。独立任务重名时追加短区分标识，不能覆盖或接管已有目录。

同一任务的研究、开发、审查、验证、用户补充意见、重试和恢复共用这个根目录。切换技能、进入下一阶段、跨日或上下文压缩不重新分配顶层目录；执行次数和运行身份放在任务内部。只有目标独立、材料归属不同的新任务才建立另一个根目录，不因名称相似合并不同任务。

首次写入时在对话中说明任务根路径，后续步骤、已授权的协作者和交接继续传递该路径及所需子路径。归属不清时先从已有任务依据和实际内容确认，不凭目录名复用其他任务材料。文件写入者与运行资源的拥有者明确，互不覆盖。

## 按用途与运行分层

`.sidekick/` 下只放任务目录，任务目录内按用途组织文件。根据实际内容选用下列子目录，首次需要写入时才创建，不预建空目录，也不为套用结构额外生成清单、README、索引或状态快照。

| 目录 | 内容与边界 |
| --- | --- |
| `inputs/` | 本任务确需保存和复用的输入、夹具或取得的原始材料；已有源码、工具和依赖直接引用，不默认复制 |
| `scripts/` | 本任务需要的一次性脚本；有长期维护价值的源码与测试归入项目正式位置 |
| `runs/<purpose>-<run-id>/` | 一次执行的原生报告、日志、截图、profile、诊断二进制和中间输出；同一轮的材料集中保存 |
| `maintenance/<run-id>/<attempt-id>/` | 针对原运行的一次清理、恢复或核对尝试，保留原运行关系，不覆盖原报告 |
| `results/` | 需要交付或继续消费的汇总结论、研究报告、图表及其他最终任务产物 |

例如一次性能任务可以按实际需要形成以下结构，不要求每项任务包含全部目录：

```text
.sidekick/
└── 202611081030-parser-performance/
    ├── inputs/
    │   └── cases.json
    ├── scripts/
    │   └── collect.py
    ├── runs/
    │   ├── baseline-01/
    │   │   └── bench.txt
    │   ├── candidate-01/
    │   │   └── bench.txt
    │   └── candidate-profile-01/
    │       └── cpu.pprof
    └── results/
        └── comparison.md
```

运行子目录用用途与实际运行 ID 或本任务内的序号区分，保留版本、输入和原生结果之间的对应关系。失败后的必要重跑使用新子目录，不能覆盖旧证据，也不另建顶层任务目录。长期运行中的 journal 按所属工具的更新契约维护，不为每次读取或恢复复制一份。

研究和绘图等专项阶段使用同一根下的相应位置；多个报告按主题在 `results/` 内区分，需要多份同名输入或不同场景时在负责该用途的子目录继续分层。不把全部文件堆在任务根，也不按 agent 名称建立一套与用途平行的分类。

## 工具与项目边界

运行证据与中间输出允许选择位置时，将它们指向当前任务的相应运行子目录；正式交付物直接生成到指定交付位置或任务 `results/`。测试框架、包管理器和工具自身管理的下载缓存、依赖环境与临时目录保留其原生位置，不复制进任务目录。

工具硬编码的目录、已登记的运行状态和恢复路径按原契约使用，通过对话或必要的任务结果说明其归属，不为统一外观复制输出、建立影子索引或手工搬动路径。调整这类工具需要同步其实现、调用方与恢复校验，不能靠改写任务说明绕过；目录规范本身不授予修改工具或项目规则的权限。

用户指定的正式交付位置直接作为产物位置，不额外在 `results/` 保留同一文件的副本。没有所属仓库且未指定位置时，在系统临时目录创建同样按任务归属组织的目录，不默认向当前无关工作区写入。

## 保留与清理

`.sidekick/` 应被所属仓库忽略，不纳入源码提交或交付包。写入前核对忽略规则，按当前任务允许的配置修改范围处理；配置不可修改时采用现有获准位置或说明限制，不因目录默认值扩大授权。目录被忽略不代表可以保留或传播凭据和业务数据，必要受限材料采用项目要求的私有权限与最小范围。

步骤结束时清理已无继续用途的输入、失败与重跑输出、一次性脚本及复制文件；后续步骤确需复用时明确消费者和接续拥有者。任务结束时保留用户要求的交付物、仍有评审用途的有效证据与未结束责任所需材料，说明路径及用途，移除其余本任务材料和留下的空目录。

清理前核对归属、引用、进程和外部资源，先结束并确认释放，再删除对应材料。仅处理本任务拥有的内容，不按时间或目录名称笼统清空其他任务；删除目录不能代替运行资源回收。保留材料不自动成为项目事实、永久档案或新的执行入口。
