# 请求性能与流式边界

## 定位请求成本

从一个真实接口和用例建立基线，记录实际 FastAPI、Pydantic、ASGI 服务、worker、代理与资源配置。明确关注完整延迟、吞吐、首字节、流完成还是事件循环响应；内存 ASGI 测试只覆盖应用路径，不能证明网络与部署表现。

沿客户端、代理、应用、依赖、查询及外部调用关联请求，区分连接与排队、Python 计算、数据库执行、锁等待、序列化及传输。分位数与错误、超时一起观察，不丢弃失败后只报告成功请求变快。

固定请求数据、身份、负载、缓存与依赖状态，先复用已有遥测。Python 进程内的归因与优化采用 [python-performance-optimization](../../python-performance-optimization/SKILL.md)，PostgreSQL 查询与锁采用 [supabase-postgres-best-practices](../../supabase-postgres-best-practices/SKILL.md)；缺少证据时先验证假设，不默认增加 worker 或替换 JSON 库。

## 验证与序列化

响应类型与 `response_model` 同时约束公开字段、验证、文档和序列化。先检查实际数据量、重复转换、ORM 加载与框架版本，避免在返回前反复执行 model、dict、JSON 字符串之间的转换。

项目版本支持时，采用框架的类型化响应与 Pydantic 序列化路径。当前官方指南推荐通过返回类型或 `response_model` 使用该路径；旧版本、自定义响应设置和项目协议可能不同，核对实际调用链及前后结果后再调整，不把最新指南当作现有环境事实。[FastAPI 自定义响应](https://fastapi.tiangolo.com/advanced/custom-response/)

直接返回 `Response` 会绕过响应模型的自动转换与过滤，装饰器中的文档声明不能补回这项保证。确需返回预编码数据或流时，由对应边界保证字段、编码、状态、媒体类型及接口说明，不通过绕过验证泄露内部字段或改变精度、日期与空值语义。[FastAPI 响应模型](https://fastapi.tiangolo.com/tutorial/response-model/)

异步响应序列化前加载所需关系，排除 N+1、隐式 I/O 与提交后的字段过期。不能将序列化触发的数据库访问误判为 JSON 编码热点，也不能全局预加载全部数据来掩盖问题。

## 事件循环与容量

核对被测路径实际调用的同步和异步代码。FastAPI 调度的普通 `def` 路由与依赖使用线程池；在 `async def` 内直接调用普通 helper 不会自动离开事件循环。同步阻塞调用与长时间 Python 计算都可能阻塞其他请求。[FastAPI 同步与异步](https://fastapi.tiangolo.com/async/)

线程池、进程 worker、数据库池和 HTTP 池分别拥有容量及等待队列。按真实瓶颈调整，并计入每进程复制的内存和连接总数；线程等待方取消也不等于底层工作已停止，不用无限执行器或批量创建无界任务隐藏排队。

外部客户端与连接池按应用生命周期复用，在依赖和任务边界正确关闭。延后工作区分响应前必须完成的事实与可持久调度的事项，不把后台执行作为移出延迟统计的技巧。

## 流式响应

先明确需要逐步交付的契约，再选项目支持的字节流、JSON Lines 或 SSE。流式不自动降低完整完成时间，首个响应发出后也无法像普通响应一样更改状态码；授权、必须完成的提交和可提前发现的失败应在协议要求的阶段处理。

生成器、数据库游标和网络响应的生命周期覆盖实际消费过程。核对当前 FastAPI 版本中 `yield` 依赖及作用域的退出时机，不能让资源在最后一块数据发送前关闭，也不为整个慢客户端流无必要地持有事务和连接。

核对客户端断连、生产者取消、背压、缓冲、最大在途数据与代理行为。测试既检查首块与结束，也检查中途失败、空流和关闭；是否有心跳、重连与事件身份由实际协议确定，不默认新增 SSE 基础设施。

## 验证

按实际变化比较请求延迟、吞吐、错误、CPU、内存、连接与事件循环行为。至少核对受影响的字段过滤、权限、真实提交与回滚、取消及资源收尾，性能优化不能削弱原有保证。

生产采样与负载验证采用授权环境和项目入口，控制资源预算。交付前后测量条件、瓶颈归因和行为证据，区分本地应用测试、真实网络测试及尚未覆盖的部署范围。
