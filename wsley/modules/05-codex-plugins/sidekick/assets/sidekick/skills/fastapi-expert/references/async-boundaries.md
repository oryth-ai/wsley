# 异步数据库边界

适用于项目实际使用 SQLAlchemy 异步会话的路径；其他驱动沿用自身的会话、事务与关闭协议。

## 会话所有权

`AsyncSession` 是具有事务状态的可变对象，不在并发任务之间共享。同一用例中顺序执行的操作可以共享会话；独立并发工作各自拥有会话，不能因此拆散本来要求原子成立的业务事实。

会话生命周期可以由请求依赖管理，事务提交责任仍需由完整用例明确决定。发生异常时回滚并正确关闭，失效事务不能继续当作可用连接。helper 使用 `flush` 获取当前事务中的写入结果时，不擅自提前提交调用者的事务。

不要让依赖退出时的隐式提交成为发送成功响应之后才发生的关键业务动作。明确当前 FastAPI 版本的依赖退出、流式响应与后台执行次序，必须成功的提交在宣布完成前取得结果。

## 查询与序列化

在明确的异步会话内加载响应所需字段和关系，避免序列化时意外 lazy load、N+1 查询或会话关闭后的访问。按实际访问模式选择显式查询或 eager loading，不全局预取所有关系。

核对提交后字段过期策略，避免返回对象时触发隐式 I/O。数据库唯一约束、外键和数量约束仍是并发保护的一部分；只将可识别的约束错误映射为对应业务拒绝，不用宽泛异常捕获隐藏真实故障。

## 外部调用与取消

外部调用使用项目规定的 TLS 验证、连接池及截止时间，避免在持有数据库锁时等待不受控的远程结果。调用超时后确认是否存在结果未知，沿原事项继续确认。

释放会话、连接和其他资源时保留取消语义，不把 `CancelledError` 转成成功或新的操作。确需保护短暂清理步骤时采用有界方案，不能无限屏蔽进程停止。

## 验收场景

使用真实数据库验证回滚、提交可见性、约束冲突与并发更新。测试用例检查提交后响应丢失、会话复用、异常退出和响应序列化，避免只有返回状态正确而持久结果错误。
