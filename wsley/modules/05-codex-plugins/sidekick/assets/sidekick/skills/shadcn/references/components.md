# 组件契约

## 实际接口

先阅读本地组件导出、props、基础库及相关调用方，再对照匹配版本的官方文档。项目内已复制的源码可以有自身定制；官网最新用法与本地不同时，先定位版本或改动，不通过猜测属性或重装组件掩盖差异。

| 方面 | 需要核对的契约 |
| --- | --- |
| 基础库 | Radix、Base UI、React Aria 等实现具有不同的组合、触发器和状态接口，使用项目实际采用的实现 |
| 元素与触发器 | `asChild`、`render` 等接口按本地组件确认，检查真实 DOM、元素语义、事件与 ref 传递，避免嵌套交互控件 |
| 导入与边界 | 使用实际别名、导出与图标库；客户端状态、事件和浏览器 API 放在项目要求的边界，不把所有组件一律改为客户端组件 |
| 版本与样式 | Tailwind、主题变量和组件变体以项目实际实现为准，不混用不同代际配置或新增平行全局样式入口 |
| 依赖与资源 | 区块引用的子组件、hooks、工具、字体与数据均有真实来源，必要许可与声明随采用的内容保留 |

文档、示例和本地组件中的通用模式可能适用不同版本。核对实际能力后使用，不能把某个示例中的属性、图标标记、分组或命名推广为所有项目的硬规则。

## 组合与行为

优先用实际存在的组件、变体与组合接口表达当前任务。列表、分组、触发器、内容区和 provider 保持组件所要求的关系；不要为了套用完整示例而加入没有职责的区域，也不要只保留外观后丢失必需结构。

弹层具有可访问名称、关闭与焦点返回行为，表单保持标签、描述、错误及控件关联。选项、菜单和页签的受控状态、键盘及禁用行为符合实际组件契约；选中、展开和业务状态分别处理，不仅依赖自定义颜色表达。

加载、空结果、失败和完成反馈由实际业务状态驱动。核对是否真的存在 `isLoading`、`isPending` 等属性，不能把其他库的 props 移植过来；需要组合反馈时保持原动作、禁用语义与恢复能力。

图表与数据表沿项目实际数据、分页、排序和过滤契约接入。示例中的数组、时间范围、金额和模拟提交明确替换或标识，未读、未知与零不混同，不能因区块展示了图表或按钮就声称相应功能已实现。

## 主题与定制

复用项目的语义变量、变体和主题入口，将业务状态、强调与表面角色对应到实际设计系统。明暗模式、焦点、禁用、错误和选中一起核对，不按官网默认主题覆盖已经确认的产品身份。

布局使用清楚的容器与间距，视觉变化归入负责该表达的变量、变体或组件源码。必要定制允许在当前任务内实施，核对受影响调用方；不将上游对某个工具类的偏好变成项目通用禁令，也不靠不断增加选择器优先级修复共用组件。

实际渲染与操作按 [frontend-design 的验证流程](../../frontend-design/references/verification.md) 检查。成熟组件提供行为基础，不能替代对当前组合、业务接入、主题及可访问性的验证。
