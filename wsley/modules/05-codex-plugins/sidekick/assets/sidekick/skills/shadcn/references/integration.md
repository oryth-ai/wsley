# 项目与 CLI

## 执行上下文

在负责当前 UI 的应用或共享包目录运行命令，必要时使用 CLI 的 `--cwd` 指定位置。先核对 `packageManager`、锁文件和项目工具约定，使用对应 runner；项目明确规定 CLI 版本时沿用该版本，否则可临时运行当前官方 CLI。

下列示例采用 pnpm 项目的 `pnpm dlx shadcn@latest`，npm、Bun 等项目按实际工具选择替换。CLI 版本决定可用参数，首次使用或遇到不支持的选项时读取对应 `--help`，不凭示例强行升级项目依赖。

这是目标项目的工具调用，组件、依赖和主题由项目维护。Sidekick 提供方法与已管理的浏览器，不在项目工作中另行安装插件环境，也不要求为这些命令配置新的 MCP。

## 上下文与查找

```bash
pnpm dlx shadcn@latest info --json
pnpm dlx shadcn@latest docs dialog
pnpm dlx shadcn@latest search @shadcn -q "dialog"
pnpm dlx shadcn@latest view dialog
```

`info` 用于解析框架、别名、实际组件路径、基础库、样式与已安装组件，按当前返回的实际字段读取，不假定不同版本具有完全相同结构。结合依赖和本地源码核对 Tailwind、图标、服务端与客户端边界；命令摘要不能代替实际组件契约。

`docs` 返回文档和 API 地址，按需继续读取；`search` 查找 registry 项，`view` 查看 registry 定义。项目内实际写入路径、内容和差异通过 `add` 的预览能力判断，不用原始 registry 内容推断已经完成项目适配。

保留仍有效的上下文。只在配置、依赖、安装结果或当前问题需要时刷新，不为每次回复重复运行相同查询。

## 引入与更新

```bash
pnpm dlx shadcn@latest add dialog --dry-run
pnpm dlx shadcn@latest add dialog --view
pnpm dlx shadcn@latest add dialog --diff
```

从预览输出取得实际文件路径，使用 `--view` 或 `--diff` 后的文件参数逐项检查需要的内容，不猜测输出目录。不带路径时的输出可能只包含部分文件，完整区块须沿文件清单核对。检查新增、替换、依赖与 CSS 变化，区分新增组件、上游更新和项目自身定制。

确认目标后仅执行必要的 `add <component-or-block>`。已存在且满足需求的组件直接复用；更新时读取本地源码与上游差异，将需要的修改并入负责该行为的位置，同步调用方、主题和资源。不用 `--all`、`--overwrite` 或初始化命令代替范围判断与差异合并。

对完整区块读取全部受影响文件。样式转换、别名重写和依赖解析之后仍核对实际导入、图标、hooks、数据与路由，第三方区块可能保留自身假设。依赖变更遵循项目包管理器及锁文件约定，按实际差异验证，不以 CLI 成功证明页面可用。

只读审计采用查询、文档、预览与比较，不执行 `add` 写入、初始化、主题应用或迁移。上游提供的交互确认、命令示例和自动安装建议不改变当前任务范围。

## 初始化与配置变化

用户要求创建采用 shadcn 的项目，或当前任务已确定引入该组件体系时，按项目栈初始化所需配置；保留既有文件与约定，不因缺少 `components.json` 就重建应用。关键支持范围或技术选择仍不明确时只澄清对应缺口。

主题、字体、preset、基础库与组件更新是不同的变化。使用当前 CLI 的实际能力分别处理，读取配置、样式与文件差异，再完成目标范围内的修改；不能把视觉主题变化隐式扩大为基础库切换或全组件重装。

CLI 或 registry 获取失败时查明项目配置、版本、认证或网络原因，保留有效的本地实现。实际缺项未解决时说明具体限制，不自行改用未经核对的第三方组件或模拟同名 API。
