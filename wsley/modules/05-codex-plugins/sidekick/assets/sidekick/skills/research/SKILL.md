# Research

围绕明确问题查阅一手资料，将结论、依据和未解决的问题整理为一个 Markdown 报告，使后续决策能追溯到原始证据。报告按当前请求和项目约定交付；用户要求仅在对话中回答时，不因技能匹配自行新增文件。

## 问题与证据

1. **界定问题**：读取适用的 `AGENTS.md`、项目文档和已有研究，确认研究问题、相关版本、约束及完成条件。能从上下文确定的内容直接采用；缺少会改变研究方向的关键条件时再询问。
2. **确定产物位置**：当前任务需要文件报告时，区分长期项目文档与任务材料，按下文规则选择目录与文件名，检查已有同主题报告。研究开始时说明范围和预期路径，不为选用默认路径额外请求确认。
3. **查阅一手资料**：优先使用官方文档、规范、维护者源码、原始论文或服务提供方 API。搜索摘要和二手文章只能提供线索，关键结论必须回到拥有该事实的原始来源。涉及当前版本、兼容性或易变化的信息时核对最新资料，并区分项目实际使用版本与上游最新版本。
4. **整理证据**：把事实、推断和建议分开，记录来源、适用版本及限制。来源冲突时检查时间、版本和适用条件；无法消除的冲突如实保留。资料不可访问或证据不足时明确缺口，不编造链接、引用或验证结果。
5. **核对并交付结论**：检查关键事实是否有直接支持它的引用、问题是否已回答、结论是否超出证据范围。需要文件报告时按下文结构写入单个 Markdown 文件，并返回报告链接；交付主要结论与仍影响决策的缺口。

## 并行阅读

委派是资料阅读的可选方式。当前任务允许使用子代理，且存在独立阅读任务和明确的并行收益时，才采用委派。提供研究问题、版本与范围、来源标准和完成条件，优先通过协作消息接收发现与依据；仅在用户要求文件、工具运行需要文件或具体后续步骤无法通过消息有效承接时分配输出路径，不要求子代理按阶段另写报告。由一个写入者负责最终报告，避免并发覆盖。

主代理收到结果后核对关键来源与产物，再报告完成。没有子代理工具、没有独立任务或没有其他并行工作时直接完成研究；不因缺少委派能力中止，也不把启动后台任务当作研究已完成。

## 产物位置与更新

按当前请求确定报告属于长期项目文档还是任务材料。用户指定的交付位置直接采用，纳入项目文档时遵循其事实来源、内容和修改授权。任务报告采用 [任务材料组织](../disciplined-dev/references/task-artifacts.md)，默认位置为：

```text
.sidekick/
└── YYYYMMDDHHmm-<task>/
    └── results/
        └── <topic>.md
```

研究属于已有开发、审计或设计任务时，复用其任务根；独立研究在首次写入时分配新任务根。取得的必要原始资料归入 `inputs/`，探针与执行证据归入相应 `runs/` 子目录，不因开始研究或切换主题在顶层另建目录。

主题标识使用简短、有含义的小写 kebab-case，例如 `oauth-token-refresh`。同一任务有多个报告时，用不同主题文件名或必要的主题子目录区分，不能互相覆盖；仅有对话交付时不创建报告、目录或来源清单副本。

报告 ID 优先采用用户或项目指定的标识；未指定时，任务报告由任务标识和主题确定，项目报告按其所属约定确定。同一报告更新保持路径与 ID，修订失效结论和引用并更新日期，在报告中注明时区。主题相似本身不构成覆盖授权；指定路径已被占用且未授权更新时说明冲突。多个写入者由一个责任方分配互不覆盖的路径，最终报告保持单一写入者。

## 报告与交付

报告语言采用用户明确要求或项目约定，未指定时使用中文，长度与问题复杂度相称。保持一个自足文件，包含：

- **研究信息**：ID、主题、研究或更新日期与时区、问题范围、适用版本。
- **结论**：直接回答问题；证据不足时指出当前能确定到什么程度。
- **发现与依据**：按子问题组织，在每个关键事实附近引用直接支持它的来源。网页使用指向具体页面的 Markdown 链接；仓库代码标注相对路径、符号及必要的行号，适合时记录 commit，以便复查。
- **限制与未决问题**：区分未找到证据、来源冲突、尚未实测和不在本次范围内的内容。仅在影响判断时提出后续验证建议。

比较方案时可用表格，提出建议时写明它依赖哪些已核实的事实。来源清单可以辅助查找，但不能代替结论旁的引用。不用搜索结果页代替原文，也不将阅读文档描述为已运行验证。

## 操作边界

按当前请求收集资料和交付研究产物，不从技能本身推导实现方案、修改业务代码、提交、推送、发布或发送消息的授权。需要探针时优先使用只读检查或隔离的临时环境；外部副作用遵守当前任务授权。材料的忽略、保留和清理采用通用任务材料规则，不因保存报告扩大项目配置修改范围。
