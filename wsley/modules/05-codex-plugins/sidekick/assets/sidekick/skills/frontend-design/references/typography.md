# 排版

## 字体与角色

从实际字体文件、`@font-face`、加载请求与浏览器渲染确认可用字族、字重、样式和字符覆盖。CSS 声明了字体不代表相应字形已经使用它；中英文、数字、符号和 emoji 可能落到不同回退字体。先解决缺失资源、错误字重映射与字形回退，再调整间距。

按标题、正文、标签、操作、数字和代码确定角色，复用项目现有层级。字族数量服从内容，不强制搭配两种字体；辨识度可以来自字形、宽度、字重、构图与留白的组合。语义标题表达文档结构，视觉尺寸由上下文确定，两者分别核对。

变量字体先查实际轴与范围。优先使用 `font-weight`、`font-stretch`、`font-style` 和 `font-optical-sizing` 等高层属性；只有需要控制字体特有轴时才直接设置 `font-variation-settings`，避免覆盖已有轴值。[字体轴说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-variation-settings)

## 行长、密度与换行

用真实文字在目标尺寸阅读，联合调整字号、容器、行高和字距。行长建议是起点，中文、拉丁文、混排、表格与移动端分别判断，不将某个字符数或行高阈值作为所有文本的合格线。小字号、轻字重、低对比同时出现时优先改善可读性，不用强制抗锯齿设置掩盖字体选择问题。

按内容选择换行策略：标题可在支持范围内使用平衡换行；正文保留自然阅读节奏；长 URL、无空格标识和用户输入需要明确的溢出处理。先检查容器和子项的收缩约束，再决定 `overflow-wrap`、滚动或截断，避免对所有文本使用 `word-break: break-all`。

截断用于确有空间约束的预览，不能移除完成任务所需的唯一信息。必要全文提供可通过键盘和触摸获得的入口，`title` 属性或仅 hover 的提示不足以覆盖全部输入方式。检查链接、按钮和状态文本换行后是否仍能识别和操作。

## 数字与语言

金额、计时、计数和比较列按实际精度、单位及对齐需要选用数字形式。字体支持时，`font-variant-numeric: tabular-nums` 可稳定动态数字或列对齐；比例数字更适合部分连续文字。不能靠补空格对齐数值，也不因排版改变金额精度。

保留真实 `lang`、方向和本地化规则。用户名称、编号与双向文字混排时，在合适的文本边界采用方向隔离；文字方向变化不等于镜像全部图标和数据。大小写、标点、引号和字距遵循实际语言，不能将英文标题格式套到全部 locale。

## 实际核对

检查字体加载前后、长短标题、多行操作、混排、缺字与缩放，观察布局偏移、基线和可读性。移动端字段出现意外缩放时，在目标浏览器复现并调整可读字号与布局，不通过禁止页面缩放解决。按任务范围复用 [组件状态与压力验证](component-states.md) 中的内容场景。
