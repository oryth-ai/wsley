# 参考与设计还原

## 依据与范围

确认参考是设计文件、运行中的页面还是截图，以及要求精确还原、适配现有产品还是只借鉴某种机制。保留参考视口、目标区域、内容、主题和状态；已提供足够依据时直接工作，不把获取原始设计文件变成所有实现的前置条件。

设计文件能提供布局约束、变量和组件关系；运行页面能提供当前渲染与交互；截图只展示某一时刻的像素。不能从截图确定真实字体文件、DOM、API、未展示状态或响应式规则，相关选择标为重建假设。需要解释外站实现时使用 [interface-analysis](../../interface-analysis/SKILL.md)。

## 取得设计依据

有 Figma 或其他设计工具连接时，先发现实际可用能力，再按需取得目标节点的设计上下文、截图、变量、资源及组件映射。工具接口以当前连接为准，不预设某个 MCP 或命令一定存在。连接不可用时使用已提供的截图与导出材料，说明缺失信息及其影响。

优先用布局约束、间距、尺寸关系和组件映射理解结构。设计工具的绝对坐标是观察依据，不要求页面复制全部坐标；Auto Layout 等约束也需结合实际内容和容器还原。组件映射比相似名称更有力，仍须核对项目源码中的真实 API。

资源按实际授权和许可取得，沿用项目资源归属。临时下载地址可能失效，必要的正式素材落到项目规定位置并保留来源；不要热链会过期的预览地址，也不把整张设计截图当作可交互页面。准确文字、按钮与数据由真实界面实现。

## 还原与适配

先搭建容器、阅读顺序、网格、字体和主要素材，再校准间距、裁切、边界和细节。复用项目已有 token 与组件；已有能力确实不足时，在适当职责内扩展角色或变体，不因“只能用现有值”牺牲必要还原，也不随意替换项目体系。

参考与业务契约冲突时，明确差异并按已确认要求处理。设计未画加载、错误、权限或空结果，不意味着删除这些分支；图片中的模拟按钮也不证明后端已有能力。涉及实质行为和方向的未决冲突先确认，其他独立部分继续推进。

截图没有覆盖的视口按实际内容和项目规则适配。区分参考测得尺寸、根据关系推导的尺寸和自行选择的值，不以未经确认的像素精度掩盖推测。

## 差异核对

在相同内容、视口、主题和状态下查看实际渲染，优先定位结构、字体回退、行宽、图片裁切和局部溢出的原因，再调整细节。整体缩放不能代替正确的布局和排版。

差异工具可帮助定位，但字体光栅化、抗锯齿和动态内容需要人工判断。按任务的准确度要求验收，不设置通用像素阈值，也不为取得更小截图差异删除业务状态或任务外文件。交付说明还原依据、必要适配、实际验证及仍依赖原始资源的部分。
