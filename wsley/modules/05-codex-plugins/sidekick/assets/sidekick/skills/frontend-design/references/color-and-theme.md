# 色彩与主题

## 角色与契约

从实际主题入口、变量、组件消费者和品牌素材确定颜色由谁维护。沿用项目已有语义名称及主题切换方式，区分背景、表面、文字、边界、操作与业务状态；不为套用词汇将 `primary` 批量改名，也不预先创建无人使用的色阶与角色。

品牌原色、装饰色和承载可读内容的功能色分别处理。固定品牌色不适合某种文字组合时，先调整使用位置、背景、文字或必要的功能变体；是否改变品牌事实由任务决定。错误、选中与成功保留文字、图形或状态等非颜色表达。

调整已有 token 时追踪所有实际消费者。原值可能同时用于文本、图标和背景，一处对比改善可能破坏另一处；需要拆分角色时按用途和调用方完整切换，不能只修一个画面。shadcn 项目按其实际主题契约处理，不新建平行变量体系。

## 主题与色域

明暗主题各自建立表面层次与文字关系，不将全部颜色机械反相。检查悬浮、按下、选中、焦点、禁用、输入、浮层和遮罩，以及系统高对比度下的实际结果。

沿用项目支持的颜色格式与浏览器范围。OKLCH 等空间可帮助调整感知明度和色度，但不构成迁移全仓颜色的理由；固定明度或色度也不保证任意色相的对比相同。超出目标色域的颜色核对实际显示与回退，不用设计值直接证明渲染结果。

## 对比测量

对具体元素和状态取得实际前景及其绘制背景，再按项目目标测量。透明文字、父级透明度、渐变、图像、遮罩和混合模式会改变最终颜色；只比较变量声明或两个十六进制值可能选错组合。渐变与照片覆盖文字时检查可能出现的最不利区域，动态内容还需核对变化范围。

优先使用现有检查器或浏览器工具，说明元素、状态、主题、颜色来源、测量方法与结果。截图采样受缩放、色彩处理和抗锯齿影响，不能把字缘像素当作 CSS 原始文字色；无法取得可靠背景时说明测量限制，不编造比值。

适用阈值与例外按 [访问与交互模式](../../accessibility/references/interaction.md) 和项目要求核对。WCAG 对比度与 APCA 是不同计算和判断体系，结果不能互换或以 APCA 启发值宣告符合 WCAG。占位文字不能因为是 `placeholder` 就自动免于文字对比要求。[WCAG 对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 修正与验证

先定位错误角色、继承或叠加关系，再调整负责该用途的值。比较修正前后的实际配对与相关消费者；清晰的焦点、边界和状态比额外增加一套色板更有用。交付说明区分已测量配对、视觉建议及未覆盖主题，不能凭一张截图宣称全站对比合格。
