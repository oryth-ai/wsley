# 表面与动效

## 表面层次

根据分组、容器、浮层与可操作性决定边框、底色、阴影和圆角，避免每一层同时叠加所有手法。浅色图片是否需要边界取决于背景、裁切和信息关系，不能统一附加某个透明度的描边。

嵌套圆角按实际内外轮廓、间距与裁切检查。外半径减间距可以作为等距轮廓的起点，但边框、非均匀间距和复杂形状需要实际调整，不套用固定阈值。阴影说明层次或悬浮关系，不用于伪造点击能力。

图标按字形、视觉重量、尺寸与文本基线组合。字体字重和图标描边没有通用的一一映射；沿用当前图标集的设计语法，在真实尺寸下判断，不为统一数值重绘整套图标。

## 动作与状态

先明确动效解释的变化：操作响应、展开收起、对象移动、页面进入还是叙事。高频操作保持及时，等待中的动效表示等待，不能替代进度事实。时长、幅度与曲线来自距离、节奏、设备及既有语法，不规定每个按钮都缩放或每段内容都入场。

| 场景 | 实现判断 |
| --- | --- |
| 简单状态间切换 | CSS transition 可直接跟随状态变化，实际验证快速反向和中断 |
| 多阶段进入、退出或序列 | 采用项目已有的 keyframes、Web Animations API 或动效库，明确开始与结束责任 |
| 滚动或手势持续驱动 | 保持输入与反馈对应，检查边界、取消、焦点及触摸行为 |
| 复杂路径、弹簧或跨组件协调 | 先核对现有能力，只有确需时引入依赖并限制作用范围 |

使用 keyframes 不表示动画无法反向；是否可重定向取决于实际状态建模与 API。Web Animations API 的 `reverse()` 可反向播放，但中断位置、播放速率和收尾仍需核对。[反向播放说明](https://developer.mozilla.org/en-US/docs/Web/API/Animation/reverse)

进入动画与交互中的状态动画分别控制，不能让每次数据刷新都重新播放入场。图标切换需要运动时先利用已有结构，保留操作名称、焦点和可点击区域，不为一个图标强制新增库。

## 生命周期与偏好

快速点击、反向切换、路由离开及组件卸载后，状态仍须正确。清理监听、计时器和任务拥有的动画，退出效果不能永久扣住节点、焦点或滚动。不要依赖动画结束作为业务成功的唯一判据。

按目标浏览器评估属性与绘制成本，避免每帧混合读取布局和写入样式。`transform` 与 `opacity` 常适合运动，但不保证复杂页面没有成本；滤镜、阴影、混合与大面积模糊按实际画面和性能证据取舍。

尊重 `prefers-reduced-motion`，减少装饰性移动或以低运动表达替代，同时保留必要状态和反馈。主题切换如果引起整页无意义的颜色过渡，在现有主题管理范围内处理，不永久禁止全部 transition。

## 验证

在正常速度下观察开始、结束、中断、反向和减少动态效果，连同实际输入与异步状态检查。静态截图验证最终构图，动态行为依赖真实过程证据；不以采用某个动画技巧直接宣称性能改善。
