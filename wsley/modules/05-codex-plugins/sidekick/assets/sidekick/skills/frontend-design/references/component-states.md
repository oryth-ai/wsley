# 组件状态与压力验证

## 状态与边界

从真实组件、调用方和产品契约列出本次需要的状态与触发条件，区分已有分支、要求存在但尚未实现的状态和任务外设想。预览状态不等于证明转换正确；涉及顺序、取消、竞争或恢复时，还需从真实事件验证相应变化。

按适用范围检查首次加载、有效空结果、部分数据、失权、读取失败、提交中、已受理、结果未知、业务失败与完成。完成后读取失败不能反推提交失败，重试也不能默认创建新事项；保留实际操作身份和恢复语义。

## 预览承载

优先使用已有 Storybook、组件运行器、开发预览或项目测试夹具。渲染真实组件，保留实际主题、字体、样式、路由及必要 provider；不要复制一份相似 JSX 作为通过证据。

从实际 props、数据适配层、请求替身或项目已有注入点控制状态。等待夹具应保持未决直到相应操作，失败与空结果保持不同契约；不能只改标签或使用短暂延时冒充目标分支。固定时间、数据和随机源仅限本次可重复场景，不泄漏到生产行为。

尊重框架的服务端与客户端边界。交互控制器可以在合适的客户端边界实现，不能为方便预览把整个组件树改为客户端；服务端组件沿项目支持的预览或集成路径验证。真实鉴权、读写和外部副作用仍受当前环境授权约束。[Next.js 边界说明](https://nextjs.org/docs/app/getting-started/server-and-client-components)

只有现有承载无法覆盖具体目标时才建立最小临时预览。明确其消费者、运行方式和清理时机，临时脚本、输入与证据采用 [任务材料组织](../../disciplined-dev/references/task-artifacts.md)；框架必须从原生位置发现的预览文件按其实际要求处理。避免默认增加生产路由、独立应用或一套全局开发开关。文件确有需要时才创建，长期保留的预览应具有明确维护用途。

## 选择压力场景

按组件职责选择可能失效的维度，不做所有组合的笛卡尔积：

| 维度 | 有意义的输入与观察 |
| --- | --- |
| 文本 | 短值、多行、长 URL、无空格标识、中文混排、emoji、实际支持语言及必要双向文字 |
| 集合 | 空、单项、分页边界、大量或部分记录，核对选择范围、滚动和操作入口 |
| 数值与时间 | 按契约区分零、缺失、未知、边界值、单位和时区，不用非法数据制造虚假缺陷 |
| 容器 | 实际窄宽容器、侧栏展开、缩放、嵌套布局，区分视口宽度与组件可用空间 |
| 偏好与主题 | 项目支持的主题、减少动态效果、高对比度和语言方向 |
| 生命周期 | 快速操作、取消、迟到响应、身份或范围变化、离开与返回，按实际并发契约取舍 |

临时伪本地化可暴露长度和遗漏问题，但不等于新增产品语言或通过翻译校对。异常输入按真实契约拒绝，拒绝后的反馈也需验证。

## 观察与收尾

先验证单个状态的内容、操作、焦点和可访问名称，再从真实入口覆盖必要转换。查看容器溢出、文本遮挡、加载抖动、键盘出口与结果恢复；状态切换器显示“成功”本身不证明业务成功。

关联实现稳定后集中核验，失败时区分产品缺陷、夹具错误和预览环境差异，修正后复测受影响场景。交付已覆盖的组件、状态、输入和限制，保留有持续价值的回归测试；释放任务拥有的进程、移除无继续用途的临时预览，不清理其他任务材料。
