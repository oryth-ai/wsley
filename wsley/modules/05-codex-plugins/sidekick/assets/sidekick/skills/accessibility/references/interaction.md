# 访问与交互模式

使用项目要求的 WCAG 版本和目标级别。标准条文与适用例外以 [W3C WCAG 参考](https://www.w3.org/WAI/WCAG22/quickref/) 为准，复合控件的键盘与状态按 [ARIA APG](https://www.w3.org/WAI/ARIA/apg/) 核对。

## 语义与名称

页面有合理的标题层级和地标，重复导航提供适当的跳过方式。导航使用链接，动作使用按钮；给原生按钮再添加 Enter 与 Space 的重复处理可能造成双重激活。

图标操作有可访问名称，名称保留可见标签的关键文字。图片根据用途选择描述、空替代文字或相邻的长说明；复杂图表提供结论及可访问数据，装饰元素不重复制造读屏内容。

标明页面与局部语言，表格保留标题、表头和关联关系。不要为版式方便移除必要语义，也不把所有文本和控件都额外包成 ARIA 控件。

## 键盘与焦点

Tab 顺序跟随实际阅读与操作关系，避免正数 `tabindex` 人工重排。所有动作能通过适用的键盘方式触发，复合控件采用对应模式的方向键和焦点策略。

模态对话框有名称，打开时焦点落在合适位置，背景交互受到限制，关闭后回到合理的触发位置。模态内的焦点约束不应变成无法退出的键盘陷阱；原生 `<dialog>` 的行为仍需按具体浏览器和实现验证。

焦点清楚可见，固定头尾和浮层不完全遮挡聚焦元素。路由变化、列表刷新与删除对象后恢复到合理位置，不让焦点掉到无关页面顶部或失效节点。

## 表单与反馈

字段有程序关联的标签，必要说明与错误通过适当关系关联；`placeholder` 不代替持久标签。组合字段按语义分组，必填与格式要求在输入前可理解。

提交错误使用真实错误信息、`aria-invalid` 和适用的错误定位。可将焦点放到错误摘要或首个错误，但不能每次输入都抢焦点。动态状态用适当 live region 通知，重复消息不造成持续打断。

登录与验证允许符合安全契约的粘贴、自动填充和替代方式，不额外设置记忆或认知障碍。同一流程已经提供的信息按适用规则复用，安全复核和失效信息的例外分别判断。

## 视觉与运动

WCAG AA 的普通文本对比度阈值为 4.5:1，大文本为 3:1；大文本通常指至少 18pt，或至少 14pt 的粗体及相应语言的等效尺寸，不能把 pt 直接写成相同数值的 px。控件与关键图形的非文本对比度另按对应条文检查。[对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

WCAG 2.2 AA 的目标尺寸条文以 24 × 24 CSS 像素或适用的间距条件及例外判断；行内文字、等价控件和由浏览器控制的目标等情况需按原文核对，不把所有元素统一放大当作合规证明。[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

状态不只依赖颜色，文字放大和重排保留内容与操作。尊重高对比度和 `prefers-reduced-motion`，关闭装饰性运动时保留表达状态所需的信息；视频字幕、描述和音频文字稿按真实内容用途提供。

拖拽有适用的非拖拽替代方式。悬浮或聚焦出现的必要内容能被读取、移入和关闭，时间限制与自动更新按任务及标准要求提供控制。
