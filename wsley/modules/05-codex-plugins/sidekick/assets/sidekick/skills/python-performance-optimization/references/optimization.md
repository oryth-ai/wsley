# 优化与取舍

## 算法与数据访问

从实际输入规模和访问分布判断复杂度。重复成员查询可考虑 Set 或字典，但计入构造、散列、内存和维护成本，保持去重、相等、顺序与错误语义；不能把不同输入的最坏与最好情况直接比较。

减少重复解析、查询、序列化和完整复制，复用作用域内稳定的结果。推导式、`map`、局部绑定和函数内联是否更快取决于解释器、回调及数据，不以语法形式替代测量，也不为微小收益破坏职责边界。

NumPy 等已有原生能力适用于已证实的批量计算成本。核对 dtype、整数溢出、浮点误差、缺失值、广播、复制与转换，计入输入输出和缓冲区成本；原生库自己的线程池也可能与服务 worker 争用 CPU，不默认新增数值栈或 C/Rust 扩展。

## 缓存与复用

缓存明确容量、键、身份与数据范围、时效和失效责任，分别测量冷启动、命中、未命中、高基数及并发请求。无界缓存可能将时间成本变成长驻内存；比较缓存前后时使用相同的操作数和可解释的命中分布。

`lru_cache` 保证内部结构一致，不保证并发相同键只计算一次。它会持有参数和返回值，缓存实例方法也可能延长实例寿命；可变结果需要明确所有权，不直接缓存协程对象、生成器或带副作用操作。[functools 缓存说明](https://docs.python.org/3/library/functools.html#functools.lru_cache)

弱引用允许无强引用的对象消失，不能充当必须命中的缓存或资源关闭协议。需要请求合并时明确调用者取消、共享结果和失败传播，不将请求去重当作业务幂等保护。

## 内存与流式处理

先查找无界集合、订阅、任务、缓存及仍被引用的结果，再选择流式消费、分块或缩短生命周期。生成器本身较小不代表整个流水线有界，消费者物化、预取、缓冲与大单条记录仍可能产生峰值。

延迟求值可能推迟异常、改变资源存活期或使输入只可消费一次。流式路径明确文件、游标和网络响应的关闭、取消及部分结果语义，不能用移出计时范围掩盖未完成工作。

`__slots__` 用于确实受实例数量和布局影响的场景，核对动态属性、继承、弱引用及序列化要求。保留对象按真实所有权测量，不通过删除有效状态、反复 `gc.collect()` 或关闭收集器掩盖滞留根因。

## 并发与 I/O

区分 CPU 密集、可释放 GIL 的原生计算与外部等待。`asyncio` 组织等待而不自动并行 Python 计算；线程对 CPU 工作的收益取决于解释器构建、实际 GIL 状态及调用库，free-threaded 构建也不取消同步与共享状态责任。[Python free-threading 说明](https://docs.python.org/3/howto/free-threading-python.html)

线程、进程与异步任务的数量由工作量、CPU 配额、内存、外部容量和完成时限决定。进程池还需计入启动方式、导入、序列化、数据复制及关闭成本，不把固定 worker 数推广到所有部署，也不默认修改全局进程启动方式。

I/O 优先复用具有明确拥有者的客户端与连接池，限制并发、排队和在途数据。仅在实际调用链支持时使用异步接口；对大量输入一次性创建全部任务再加信号量，仍可能留下无界任务与内存成本。

超时、取消与停止实际工作分别处理。取消等待线程或远程调用不代表副作用已停止，保留原操作身份、结果确认和清理责任；不把失败吞掉后只统计成功请求的耗时。

## 数据库与服务

从真实查询计划、返回规模、锁及连接等待判断数据库成本。先减少无用往返和字段，再评估索引、加载和批量；FastAPI 的请求与事务采用 [fastapi-expert](../../fastapi-expert/SKILL.md)，PostgreSQL 采用 [supabase-postgres-best-practices](../../supabase-postgres-best-practices/SKILL.md)。

比较相同事务、持久性和失败语义的操作。逐条提交与一次提交并非天然等价，批量必须保持项目允许的原子性、顺序和部分失败处理；SQLite 内存样例也不能证明真实数据库部署收益。

局部改法最终回到实际用例验证。吞吐增加时同时观察尾延迟、错误、资源与关闭行为，明确是否只是把成本转移到缓存、队列、另一个进程或外部服务。
