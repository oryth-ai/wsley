# 后端评审面

根据实际产品和任务选择相关项。先确认项目承诺，再设计触发场景和取得证据；未提供的业务能力不自动成为缺陷或新增需求。

## 商业规则与领域边界

- 套餐、商品、资格、价格、计量单位和服务成本是否有明确含义及事实拥有者
- 钱包、预付款、额度、容量和席位等不同资产是否分别记账，单位、精度、舍入和有效期是否明确
- 购买、续费、取消、退款和人工处理是否遵循产品授权及已成立的商业条件
- 价格发布、软件更新和运营配置是否按各自权限生效，原订单与权益是否保留契约要求的原承诺
- 是否存在调用者重复重建业务规则、跨领域直接修改事实或同一事实多处维护

用重复购买、并发余额变化、到期边界、改价后续费和成员变化等实际支持的场景核对不变量。跨服务的资金或权益流程必须能关联原事项与实际交付。

## 身份、租户与安全

- 注册、验证、登录、找回和会话失效的条件；管理员与客户身份的边界
- 主体、动作、资源、租户、业务状态与字段级权限是否共同核验
- 撤权、停用、成员移除、资源转移与迟到请求是否存在绕过路径
- 文件上传、对象下载、回调、内部接口和外部请求的信任边界
- 签名、令牌、密钥、限流及敏感日志的实际配置与使用路径

验证已登录用户访问他人资源、跨团队访问、异步任务在撤权后交付、直接对象地址访问等情况。不能用身份验证成功代替对象授权，也不能仅凭界面隐藏证明权限生效。

## 接口与数据

- API、错误分类、分页、命令身份、幂等键和 SDK 是否表达相同契约
- 同键重复与同键异参是否可区分，提交后响应丢失是否沿原事项恢复
- 数据库约束、事务隔离、锁顺序与并发更新是否保护业务不变量
- 初始化、升级和常规启动的责任与支持范围是否明确
- 索引、查询计划、连接预算和数据增长是否符合实际负载

检查契约输入、实现、生成客户端和真实交付物。通过并发与真实依赖验证事务、锁、约束和协议边界；纯 mock 不能证明数据库或网络语义。

## 异步任务与外部副作用

- 业务提交、意图记录与入队是否按需要原子成立，任务是否有稳定身份
- 重试、重复投递、执行中断与结果未知时能否保持原目标和业务含义
- 回执、结算、释放和清理是否对应实际发生的副作用
- 领取、租约、心跳、截止时间、取消与停止是否有明确责任
- 迟到执行、资源删除和成员变化是否破坏内容或权限屏障

在副作用之前、之后和回执丢失处设置故障场景。补偿本身也可能失败或结果未知；按领域契约决定恢复动作，不以一条通用回滚规则替代已成立的业务事实。

## 运行、性能与交付

- 请求、任务、数据库、对象存储、外部服务和模型的并发、排队、时间与内存预算
- 生命周期装配、健康、就绪、入口开放、优雅停止与执行者交接
- 日志、指标和追踪能否解释用户可见失败、业务积压和未知事项
- 发布、配置、密钥、数据库及对象的版本和责任边界
- 备份是否包含一致的数据、对象、密钥与未完成责任，恢复目标是否经过隔离演练
- 管理员和客服是否能在权限范围内定位、解释和处理订单、权益与任务异常，操作是否可审计

区分容量不足、慢查询、外部延迟和 CPU/GPU 瓶颈，基于代表性测量优化。容器健康、文件备份存在或任务心跳不能单独证明业务可用、高可用或完整恢复。

## 隐私与验证

- 收集、访问、导出、删除、保留和备份中的数据是否有明确生命周期
- 数据删除与业务历史、审计保留的边界是否符合实际产品及适用要求
- 单元、属性、集成、浏览器、镜像和恢复验证是否分别证明对应行为
- 是否覆盖有效成功、当前拒绝、重复、并发、提交后丢失响应及持久恢复

采用项目要求的地区和行业规则，不把某一法规清单泛化到所有产品。评审结果注明真实覆盖范围；缺少证据的能力保持待验证状态。
