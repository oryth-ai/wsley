# Research

围绕明确问题查阅一手资料，将结论、依据和未解决的问题写入项目中的一个 Markdown 文件，让后续决策能追溯到原始证据。

## Workflow

1. **界定问题**：读取适用的 `AGENTS.md`、项目文档和已有研究，确认研究问题、相关版本、约束及完成条件。能从上下文确定的内容直接采用；缺少会改变研究方向的关键条件时再询问。
2. **确定产物位置**：按照下文规则选择目录与文件名，检查已有同主题报告。研究开始时说明范围和预期路径，不为选用默认路径额外请求确认。
3. **查阅一手资料**：优先使用官方文档、规范、维护者源码、原始论文或服务提供方 API。搜索摘要和二手文章只能提供线索，关键结论必须回到拥有该事实的原始来源。涉及当前版本、兼容性或易变化的信息时核对最新资料，并区分项目实际使用版本与上游最新版本。
4. **整理证据**：把事实、推断和建议分开，记录来源、适用版本及限制。来源冲突时检查时间、版本和适用条件；无法消除的冲突如实保留。资料不可访问或证据不足时明确缺口，不编造链接、引用或验证结果。
5. **写入并核对报告**：按下文结构生成单个 Markdown 文件，检查关键事实是否有直接支持它的引用、问题是否已回答、结论是否超出证据范围。完成后返回报告链接、主要结论与仍影响决策的缺口。

## Delegation

有可独立执行的资料阅读任务、主代理同时有其他有用工作且当前环境允许时，优先交给后台子代理。提供研究问题、版本与范围、来源标准、输出路径和完成条件；由一个写入者负责最终报告，避免并发覆盖。

主代理收到结果后核对关键来源与产物，再报告完成。没有子代理工具、没有独立任务或没有其他并行工作时直接完成研究；不因缺少委派能力中止，也不把启动后台任务当作研究已完成。

## Output location

路径按以下优先级确定：用户本次明确指定的位置、项目规范或清晰一致的既有研究存放约定、默认路径。项目只规定目录或只规定命名时，未规定的部分使用下列默认值。

```text
/tmp/research/<research_id>-<research_name>.md
```

- 默认路径位于 `/tmp/research`；需要时创建父目录。
- `research_id`：优先使用用户或项目指定的标识；否则以研究开始时的本地时间生成 `YYYYMMDD-HHmmss`，在报告中注明时区。同一次研究保持同一 ID。
- `research_name`：简短、能区分主题的英文小写 kebab-case，例如 `oauth-token-refresh`；不含路径分隔符、空格或 `..`。
- 新研究写入前检查完整路径是否存在；发生同名冲突时给 ID 追加 `-2`、`-3` 等序号，直到找到未使用的路径，不覆盖已有报告。多个写入者可能竞争时采用排他创建或由单一写入者分配路径。
- 用户明确要求继续或更新某份研究时，沿用该报告的路径与 ID，修订失效结论和引用并更新日期；主题相似本身不构成覆盖授权。

例如，一次研究可以保存为 `/tmp/research/20260908-143025-oauth-token-refresh.md`。这里的时间仅展示格式，实际执行时读取当前时间。

## Report

报告使用用户的语言，长度与问题复杂度相称。保持一个自足文件，包含：

- **研究信息**：ID、主题、研究或更新日期与时区、问题范围、适用版本。
- **结论**：直接回答问题；证据不足时指出当前能确定到什么程度。
- **发现与依据**：按子问题组织，在每个关键事实附近引用直接支持它的来源。网页使用指向具体页面的 Markdown 链接；仓库代码标注相对路径、符号及必要的行号，适合时记录 commit，以便复查。
- **限制与未决问题**：区分未找到证据、来源冲突、尚未实测和不在本次范围内的内容。仅在影响判断时提出后续验证建议。

比较方案时可用表格，提出建议时写明它依赖哪些已核实的事实。来源清单可以辅助查找，但不能代替结论旁的引用。不要用搜索结果页代替原文，也不要将阅读文档描述为已运行验证。

## Boundaries

研究请求授权收集资料和写入研究产物，不自动授权实现方案、修改业务代码、提交、推送、发布或发送消息。需要探针时优先使用只读检查或隔离的临时环境；外部副作用遵守当前任务授权。目录与命名规则只约束研究产物，不要求修改项目的 `.gitignore` 或其他配置。
