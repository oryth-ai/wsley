# Coherent Change

从最终目标组织修改，使职责、行为、消费者和说明构成一致的完整成果。“最优切换”决定最终应该是什么样，“干净切换”保证受影响范围完整到达该状态。改动行数少不是首要目标，大规模重写也不是默认手段。

## 明确目标与边界

修改前读取适用的 `AGENTS.md`、受影响文件、契约和测试，检查工作区差异，区分本次任务与已有改动。明确最终行为、公开名称、输入输出、配置含义和可观察的完成条件。仅整理格式时，保留原有行为；用户已确认的决定不因当前实现不同而失效。

在现有必要约束下，判断如果从一开始就知道完整目标，应怎样组织目录、职责、接口和内容。现有实现是事实与依赖的证据，不是设计合理性的证明。不为假设中的未来需求增加抽象。

关键行为或数据含义未确定时，指出具体缺失的决定，暂停依赖该决定的部分，继续不受影响的工作。不要同时实现多个猜测方案或通过回退逻辑掩盖不确定性。目标与适用规范冲突时明确报告，不擅自将目标降级为兼容方案。

## 让结构直接表达职责

直接在负责该行为的位置实现目标。若接入功能需要绕过职责、多层无意义转发、复制逻辑或持续增加特殊分支，先调整必要的职责边界。重构限定于目标及其必要影响范围，不重写无关模块。

目录、文件、模块和函数应承载明确职责。相关内容集中，职责不同或需要独立维护时合理拆分；避免空壳文件、无效嵌套和过度拆分。创建文件前明确实际用途，语言、构建或工具要求的文件不能仅因内容为空而删除。

通过命名、职责和控制流程表达意图，不用说明性注释弥补绕行结构。注释与文档字符串遵循项目约定，保留有实际维护价值的约束、原因及工具指令，不复述自明实现。

代码按职责和处理阶段分块，紧密相关的语句放在一起，阶段之间保留空行。声明、初始化和执行逻辑也按职责分组，不机械逐行留空，不为节省输出压缩代码或省略逻辑分组。格式化工具不能代替职责划分。

## 完整切换所有消费者

修改前搜索受影响的名称、路径、字段、配置和入口，结合调用与引用关系识别消费者。消费者包括调用功能、读取配置、依赖输出或描述行为的内容；盘点源码、测试、配置、脚本、文档、生成物和交付资源，确定需要改写、删除或重新生成的内容。

当目标替代既有方案时，使目标成为受影响范围内唯一有效的实现与说明，同步所有消费者。不要保留仅为被替代方案服务的兼容别名、旧入口转发、包装层、新旧格式双读双写、版本选择分支或隐式回退。正常业务分支、必要的边界适配和故障处理不属于历史兼容残留。

确认引用已迁移后，精确移除失效的文件、符号、依赖、配置、资源和说明。不在当前项目中保留备份副本、注释掉的旧代码、临时过渡层或“暂时兼容”的入口。

删除必须有已被替代、引用已迁走或与目标冲突等具体依据；当前没有调用或匹配文件本身不是删除理由。保留仍有效的通用规则和明确保留的能力，使用精确、可恢复的操作，不清理宽泛目录，不覆盖任务外改动。

需要保留数据时，先设计单向迁移，再使运行时只处理目标格式。不得用永久双读双写代替迁移，也不得删除用户数据来完成切换。必要的迁移历史和变更记录按职责保留，不参与运行时的新旧行为选择。

## 让内容呈现最终状态

新增与改写内容融入文件的主责位置，与上下文的术语、抽象层级、语言和格式一致。同一事项原位整合，必要时重写相邻部分，不在末尾追加补充条款来维持矛盾内容。

正文与注释面向最终使用者和维护者，直接描述有效职责、行为与约束，不记录“本次新增”“修改后”“先暂时”“后续再”等过程叙述或对话回应。必要的变更记录进入项目规定的位置，不混入当前实现说明或长期规则。

按阅读依赖与实际执行关系组织内容；执行顺序、匹配优先级和覆盖关系优先于外观排序，仅对顺序无关的同类条目稳定排序。输出、文档与注释的语言遵循目标项目规范；保留用户输入、原始文献和业务数据的原文。

配置和工程脚本的分组应对应实际职责，说明只补充正确使用所必需的填写要求、单位、前提、外部依赖或副作用。不添加装饰性横幅、空分组、自明内容说明或语法不支持的伪注释字段。

遵循项目格式配置与语法，使用 UTF-8、LF 和文件末尾换行，不手工对齐列、不留下行尾空白，不因格式整理改变含义。紧凑的中间输出只适用于格式化工具能确定性恢复的机械格式，并须在交付前完成格式化；逻辑分组及其空行在编写时保留。

## 按完整成果核验

重新通读修改后的完整文件及关联链路，核对目标是否位于正确职责、消费者是否全部同步、内容是否连贯，以及是否残留重复说明、临时分支或历史兼容行为。

对替换的标识和路径再次搜索，逐项说明剩余命中的有效用途；必要的迁移历史、变更记录和负向测试可以保留。不能仅凭某个文件不再引用就宣称切换完成。

依据实际差异执行适用的格式、静态、生成、构建或行为验证。对公开 API、CLI、配置或界面检查目标行为及旧入口是否仍可到达。如实报告检查范围与环境限制，不用未执行的检查或替代环境冒充真实系统证据。检查通过不能替代结构审查与消费者完整性核验。

交付说明列出最终变化、验证依据和实际未完成项。消费者未迁移、旧行为仍可到达或关键决定未解决时，不把局部可用当作完成。修改不自动授权 Git 提交、推送、发布或外部系统变更；不自行把开发过程回写为项目协作规则。
